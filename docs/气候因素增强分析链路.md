# 气候因素增强分析链路（云 / 降雨 / 降雪）

面向烟台非法采矿遥感预警，在既有光学变化检测之外增加一层气候解释与校正。目标不是把天气当“新证据”，而是回答三个原来答不了的问题：

1. 这一景/这一天到底能不能看见地表变化？（观测适用性）
2. 指数序列里有多少变化是雨、雪、土壤湿度驱动的？（天气归一化）
3. 不同类型矿种的漏报/误报机制不同，应该分别怎么解释和排序？（类型化方法）

> 数据诚信边界：本链路输出的是**线索排序分**，不是概率、置信度或 F1。没有独立高分/现场标签，因此不声称“预测精度提升 X%”，只报告样本外解释增益、排序变化、负对照降级和观测盲区。

## 1. 链路位置

```
Sentinel-2 场景缓存 (data/yantai_2025_v2/cache)
        │
        ├── 逐景指数中值 ──┐
        │                  ├── 天气归一化模型（谐波 + 天气协变量，LOO-CV）
Open-Meteo 日气候 ─────────┘                  │
        │                                     ▼
        ├── 逐景 SCL 云/雪占比 ──► 观测适用性 + 探测能力 + 混淆解释
        │                                     │
        └── 候选首次告警日天气 ───────────────► 候选气候校正 / 排序 / 等级封顶
                                              │
                                     candidates_climate.geojson
                                     evaluation.json / summary.md
```

实现分两层：

| 层 | 文件 | 职责 |
|---|---|---|
| 通用模型层 | `mining_watch/climate.py` | 气候取数、日特征、SCL 占比、六类画像、适用性、探测能力、天气模型、候选调整 |
| 烟台编排层 | `scripts/yantai_climate_pipeline.py` | 读 81 景缓存与已有候选，跑 fetch→scenes→scl→model→explain→evaluate→report |

`run.py --stage climate` 是轻量入口：不依赖卫星缓存，只按 AOI 中心取气候、算目标期可用观测窗口和分月统计，适合给平台做运行前检查。完整的候选级校正走 `scripts/yantai_climate_pipeline.py`。

## 2. 气候数据与特征

数据源为 Open-Meteo Archive（ERA5 再分析，日值，免密钥）：

```text
https://archive-api.open-meteo.com/v1/archive
  ?latitude=37.15&longitude=120.25
  &start_date=2022-01-01&end_date=2025-12-31
  &daily=precipitation_sum,snowfall_sum,snow_depth_max,cloud_cover_mean,
         temperature_2m_mean,temperature_2m_min,temperature_2m_max,
         soil_moisture_0_to_7cm_mean,et0_fao_evapotranspiration
  &timezone=Asia%2FShanghai
```

`build_daily_features()` 生成：

| 特征 | 含义 |
|---|---|
| `precip_1d/3d/7d/30d` | 当日及前期累计降水（mm） |
| `snowfall_1d/7d` | 当日及前期降雪（cm） |
| `snow_depth_cm` | 日最大雪深（原始单位 m，转 cm） |
| `soil_moisture` | 0–7 cm 表层体积含水量（m³/m³） |
| `cloud_cover` | 日平均云量（%） |
| `temp_mean/min/max` | 气温（℃） |
| `et0` | FAO 参考蒸散（mm） |
| `freeze_thaw` | 日最低温 < 0 且日最高温 > 0 |
| `rain_on_snow` | 有雪深且当日降水 > 0 |
| `dry_spell_days` | 截至当日的连续无有效降水天数 |
| `month` / `doy` | 月份与年积日 |

缓存默认写到 `data/climate/<aoi>/daily.json`；同一 AOI 重复运行不重复请求。

SCL 部分优先读取 Sentinel-2 L2A 的 SCL 分类，统计每景：

- `valid = {4,5,7}`（植被/裸地/未分类），与 `scripts/yantai_2025_activity.py` 的 `VALID_SCL` 一致；
- `cloud = {8,9}`，`thin_cloud = {10}`，`shadow = {3}`，`snow = {11}`，`nodata = {0,1}`；
- 只有 SCL 读不到时才回退到“候选 `valid_frac` + 天气代理云量”，并在输出里标记 `source`，不把回退值伪装成 SCL。

## 3. 六类采矿画像

`TYPE_PROFILES` 把“不同类型不同方法”固化成可执行配置，而不是只在报告里写一段话。

| 类型 | 主方法 | 次方法 | 主模态 | 最少可用观测 | 最大间隔 | 主要天气混淆 |
|---|---|---|---|---:|---:|---|
| `open_pit` 露天采坑/采石 | 光学 ΔBSI/NDVI 季节归一化、NBR 扰动、纹理边界 | SAR 后向散射、运输/夜光、用地手续 | optical | 6 | 45 d | 雨后湿土、积雪/融雪、云影、农田翻耕 |
| `river_sand` 河道采砂 | 水体/沙洲指数、河道形态、采砂船/设备 | 光学裸沙、SAR 水陆对比、水政许可 | optical | 4 | 60 d | 洪水冲淤、水体浑浊、枯水沙洲出露、河道整治 |
| `underground` 硐采/井工 | InSAR 形变/相干、井口厂房、运输用电 | 光学设施变化、夜光、矿权台账 | sar | 3 | 60 d | 冻融、降水去相干、灌溉、采煤沉陷 |
| `stockpile` 堆场/排土场/尾矿 | 堆体几何/DSM 体积、纹理阴影、运输频次 | 光学裸地、SAR 后向散射、环保台账 | hybrid | 4 | 60 d | 雨蚀沟、雪覆盖、物料正常周转 |
| `remining` 废弃矿山复采 | 历史扰动底图 + 新增道路/设备、裸地再扩张 | SAR、运输链路、复垦台账 | optical | 6 | 45 d | 季节返绿、复垦工程、历史裸地纹理 |
| `transport` 运输/外运异常 | 卡口/称重/AIS/夜光、道路轨迹、时段异常 | 光学车辆/道路、SAR 车辆、矿权台账 | logistics | 0 | 30 d | 雨雪停运、节假日、农忙 |

每类还带：

- `family_weights`：O/S/L/D/T/C/H 七族权重，与 `mining_watch/evidence.py` 对齐，供后续把气候可靠性映射回证据评分；
- `weather`：云/雪/雨/土壤湿度/冻融的敏感度权重，决定观测适用性折减；
- `signal_threshold`：该类型用于排序的变化信号尺度；
- `confounder_penalty`、`confounders`：混淆解释与惩罚上限；
- `dry_months`、`window_strength`：作业/观测窗口先验，只解释时机，不进入证据。

AOI 到类型的映射在 `config_yantai.yaml` 的 `aoi_types`，缺省时用 `AOI_TYPE_HINTS`。

## 4. 观测适用性：先回答“能不能看见”

`optical_suitability()` 输出 0–1，加权几何平均：

```text
q_cloud  = 1 − 0.95 · ramp(cloud, 0.10, 0.90)
q_snow   = 0                         if snow_frac ≥ 0.50
         = 1 − clamp(max(snow_frac/0.25, snow_depth_cm/5))
q_rain   = 1 − 0.8 · ramp(precip_7d, 5, 45)      # mm
q_soil   = 1 − 0.5 · ramp(soil_moisture, 0.22, 0.45)
q_freeze = 0.75 if freeze_thaw else 1.0

score = weighted_geomean(q_cloud^w_cloud · q_snow^w_snow · q_rain^w_rain
                         · q_soil^w_soil · q_freeze^w_freeze)
```

雪是硬约束：`snow_frac ≥ 0.5` 或 `q_cloud = 0` 时整景判 0。权重来自类型画像，所以同样是 20 mm 降水，河道采砂（rain 0.9）比井工（rain 0.7）更受影响，而井工更怕冻融（freeze 0.8）。

SAR 适用性 `sar_suitability()` 是相干性代理，不是真实相干系数：

```text
q_rain   = 1 − 0.7 · ramp(precip_3d, 2, 25)
q_snow   = 1 − 0.5 · ramp(snow_depth_cm, 0, 5)
q_freeze = 0.55 if freeze_thaw else 1.0
score    = weighted_geomean(q_rain^0.5 · q_snow^0.3 · q_freeze^0.2)，下界 0.15
```

`usable_optical` 取 `score ≥ 0.5`；`usable_sar` 同理。主模态可靠性 `primary_reliability()`：光学类取光学适用性，SAR 类取 SAR 适用性，混合类取两者最大值，物流类恒为 1。

## 5. 探测能力：区分“没检出”与“没观测”

`detection_power()`：

```text
base      = 1 − exp(−n_usable / clear_min)
gap_factor = 1                                   if gap ≤ max_gap
           = max(0.15, max_gap / gap)            if gap > max_gap
power     = clamp(base · gap_factor)

level = adequate     if power ≥ 0.75
      = limited       if 0.45 ≤ power < 0.75
      = insufficient  if power < 0.45
```

`clear_min` 与 `max_gap` 来自类型画像。这个量的含义是“在现有观测机会下，至少看见一次变化的近似概率”，不是检测精度。输出必须与候选一起报告，避免把“这个月没查出图斑”直接说成“这个月没有采矿”。

## 6. 天气归一化模型

对每个 AOI、每个指数（BSI/NDVI），用全部 81 景的 AOI 稳定像元中值建序列。稳定像元定义：在至少 70% 的场景中有效，且有效次数不少于 `max(6, round(0.70·n))`。

模型设计矩阵：

```text
y_t = β0
    + β1·sin(2πt/365.25) + β2·cos(2πt/365.25)
    + β3·sin(4πt/365.25) + β4·cos(4πt/365.25)
    + γ1·z(precip_7d) + γ2·z(soil_moisture)
    + γ3·z(snow_depth_cm) + γ4·z(cloud_cover)
    + ε_t
```

- 谐波捕捉年周期与半年周期（耕作、物候、太阳几何）；
- 天气项先做 z-score，避免量纲差异；
- 用 Huber IRLS（c = 1.345）拟合，降低云边缘、残余雪斑等离群景的杠杆；
- 同日多景先取均值，避免伪样本；
- 用留一交叉验证（LOO-CV）比较“仅谐波”与“谐波 + 天气”的 RMSE；
- **只有改进 ≥ 2% 且样本 ≥ 30 才 `applied=True`**。否则保留原始观测，不用不稳定系数去“制造”变化。

候选校正用同一模型的差分形式：

```text
shift = Σ γ_k · (z_k(告警日天气) − z_k(基线同季均值))
adj_delta_bsi  = raw_delta_bsi  − shift_bsi
adj_ndvi_drop  = raw_ndvi_drop  − shift_ndvi
```

这是场景级近似：用 AOI 稳定像元中值和“告警日 vs 基线同季”的天气差，替代逐像元辐射归一化。它不能消除所有大气/土壤湿度影响，但能把“雨后湿土压低 BSI”与“真实新增裸地”分开一部分。

## 7. 候选排序与等级封顶

`adjust_candidate()` 对每个候选计算：

```text
reliability = 主模态适用性（光学 / SAR / 混合最大值 / 物流=1）
conf        = 1 − Π(1 − strength_i)        # 多个混淆解释的合并强度

signal_raw = clamp(0.65·z(ΔBSI_raw) + 0.20·area + 0.15·persistent)
signal_adj = 同式，但 ΔBSI 换成天气校正后的值

pre_score  = 100 · clamp(0.55·evidence + 0.45·signal_raw)
post_score = 100 · clamp(0.55·evidence + 0.45·signal_adj)
             · (0.5 + 0.5·reliability)
             · (1 − 0.35·conf)
```

等级封顶：

| 条件 | 封顶 |
|---|---|
| `detection_power = insufficient` | C |
| 单一混淆强度 ≥ 0.75 | C |
| 积雪主导（snow strength ≥ 0.6）或光学主模态适用性 < 0.25 | D |

`climate_tier` 是原 `evidence_tier` 与封顶值取更保守者。所有输出保留 `climate_pre_score`，可以逐候选比较“校正前/后”，不是只给一个黑箱新分。

### 混淆解释

`explain_weather()` 把天气翻成可审计的漏报/误报说明，每条带 `factor`、`strength`、`direction`、`text`、`families`：

- `snow`：积雪覆盖，光学指数不可比；
- `cloud`：云/薄云，云影残留与漏观测；
- `rain_wet_surface`：近 7 天降水，湿土压低 BSI，返干后回升，ΔBSI 可被放大或抵消；
- `soil_moisture`：表层含水量偏高，裸地指数被压低（漏报）；
- `freeze_thaw`：日冻融交替，反射率与 SAR 相干性均变化；
- 河道采砂额外有 `flood_flow`（30 天累计降水导致冲淤/浑浊，误报）和 `dry_exposure`（连续无雨沙洲自然出露，误报）。

### 窗口先验

`window_prior()` 只描述“这个类型在这个季节/天气下是否更容易作业或被看见”，例如河道采砂在少雨、连续无雨时先验略升，运输在雨雪时先降。它**不进入证据族，不作为活动概率**，输出里固定带这句话。

### persistent_bare 候选的特殊处理

`source=persistent_bare` 的候选没有 `first_alarm/t0/t1`，不能拿“告警日天气”硬套。链路改用目标年夏季（6–8 月，缺则全年）的聚合观测：

- 天气取 `precip_7d/30d`、`snow_depth`、`soil`、`cloud`、`temp`、`dry_spell` 的均值；
- SCL 取均值；`valid_frac` 取均值；
- 逐景算 `usable_optical`，统计 `n_usable` 与最大间隔；
- 输出 `climate_observation_basis = target_year_summer_aggregate` 或 `target_year_all_aggregate`。

这样持久裸地不会因为“没有告警日”被默认 `cloud=0.5` 误判成低观测能力。

## 8. 类型化方法的实际差异

同一套代码，不同画像会产生不同结论：

| 场景 | 露天采坑 | 河道采砂 | 井工 |
|---|---|---|---|
| 连续降雨 30 天 150 mm | BSI 被压低，偏漏报；`rain_wet_surface` + `soil_moisture` | 洪水冲淤/浑浊，偏误报；`flood_flow` 强度高 | 光学本就不是主模态，影响小；SAR 去相干上升 |
| 冬季积雪 5 cm | 光学直接不可用，封顶 D | 雪盖沙洲，光学不可比 | SAR 仍可用，但冻融降低相干 |
| 春季返绿 | 与农田翻耕混淆，需 `ndvi_drop` 与物候约束 | 与河道植被恢复混淆 | 影响小 |
| 干旱少雨 | 观测窗口好，但风尘可能抬高 BSI | 沙洲出露，误报风险最高 | 无直接影响 |

这也是“不同类型不同方法”的落点：不是给每个类型换一个模型，而是用类型画像改变**观测门槛、天气敏感权重、混淆解释、可靠性折扣和等级封顶**。

## 9. 运行方式

```bash
cd /e/警务遥感

# 轻量：只取气候、算目标期观测窗口（不依赖卫星缓存）
.venv_mw/Scripts/python.exe run.py --aoi zhaoyuan --stage climate

# 完整：读取 81 景缓存 + 既有候选，跑全链路
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage all --scl

# 分阶段
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage fetch
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage scenes --force
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage scl --scl
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage model --force
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage explain
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage evaluate
.venv_mw/Scripts/python.exe scripts/yantai_climate_pipeline.py --stage report
```

参数：

| 参数 | 说明 |
|---|---|
| `--aoi mining_belt,A_control` | 默认两个 AOI |
| `--stage fetch/scenes/scl/model/explain/evaluate/report/all` | 默认 `all` |
| `--scl` | 用 Planetary Computer SAS 签名读取 SCL；失败逐景回退 |
| `--force` | 忽略已有中间产物，强制重算 |

SCL 读取需要 Planetary Computer 的 SAS 签名（`https://planetarycomputer.microsoft.com/api/sas/v1/sign`），缓存 50 分钟；429 时按 20 秒递增退避，单景失败不中断全链路。

start_server.bat

| 接口 | 内容 |
|---|---|

## 11. 评估口径（无标签，不伪造精度）

`evaluate` 阶段只做四件可复算的事：

1. **已知点最近候选排名变化**：3 个已知采石点（YT-007、B-quarry-1、B-quarry-2）不参与打分，只观察最近候选从 `evidence_rank` 到 `climate_rank` 的升降；
2. **负对照降级**：A_control 是无矿农田，统计被天气解释/降级、低于阈值的候选数与面积；
3. **雨量相关**：候选月度数量与月降水量的 Spearman 相关，校正前后对比；相关绝对值下降说明候选对降雨的依赖减弱；
4. **模型样本外增益**：LOO-RMSE 改进百分比；不显著就不启用。

2026-11 实跑结果（81 景、无独立标签）：

| 指标 | mining_belt | A_control |
|---|---|---|
| 稳定像元 | 699,783 | 96,476 |
| BSI 天气模型 | 启用，LOO-RMSE ↓3.00% | 不启用，↓−2.08% |
| NDVI 天气模型 | 启用，↓3.54% | 不启用，↓−4.54% |
| 目标期可用观测 | 41/45 景，最大间隔 35 天 | 45/45 景，最大间隔 35 天 |
| 探测能力 | 0.999 adequate | 0.999 adequate |
| 候选数 | 39 | 29 |
| 校正后低于阈值 | 28/39 | 23/29 |
| 已知点最近候选平均排名变化 | +0.33（1 改善 / 2 变差） | 无已知点 |
| 候选-降雨 Spearman | 0.070 → −0.042 | −0.250 → −0.059 |

解读：

- mining_belt 的天气项带来约 3% 的样本外 RMSE 改善，幅度不大但方向稳定；A_control 的天气项没有样本外增益，链路选择**不启用**，这是预期行为，不是失败；
- 已知点排名平均只变化 +0.33，YT-007 从 1 降到 12、B-quarry-2 从 19 升到 5，说明校正不是“全面提升”，而是按天气证据重新分配排序；不能据此声称精度提升；
- 负对照的雨量相关绝对值下降（−0.250 → −0.059），方向符合“候选不再随降雨同步涨落”的预期，但样本只有 2025 年 12 个月，不能外推；
- 校正后 28/39 与 23/29 低于排序阈值，说明气候校正主要在做“降权/降级”，而不是制造新候选。

## 12. 使用边界

1. **排序分不是概率**。`climate_adjusted_score` 不能解释为“非法采矿概率”，也不能直接做阈值执法。
2. **场景级近似**。指数序列用 AOI 稳定像元中值，候选校正用告警日相对基线同季均值，不能替代逐像元辐射归一化或真实大气校正。
3. **雨雪方向因类型而异**。露天采坑雨后湿土压低 BSI，可能漏报；河道采砂洪水冲淤、沙洲出露可能误报；井工 SAR 受降水去相干和冻融影响。
4. **天气模型可能不启用**。LOO-CV 不达标时保留原始观测，这是数据诚信要求，不是链路故障。
5. **SCL 回退要标注**。读不到 SCL 时用天气代理，输出 `source` 与置信度会不同，不能与 SCL 结果混在一起比较。
6. **已知点只评估不排序**。3 个已知采石点仅用于观察排名变化，不参与候选打分。
7. **输出即线索**。候选只表示“疑似地表扰动/异常”，不构成违法认定；合法性仍需矿权、许可、现场核查。
