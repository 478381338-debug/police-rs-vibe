## 1. 结论与建议决策

**现状基本符合《改动说明》描述的“首轮试点浮窗”，但只部分实现原实施方案，尚不是完整的滚动预警系统。** 原方案第二十节追加了首轮实现记录，不能因此把前文尚未落地的目标视为已经完成。

应保留现有 FastAPI、Leaflet、ECharts、案件工作台和移动核查能力。把烟台专题从浮窗升级为独立工作区，再补齐影像质量、逐景监测、活动解释、许可核对与核查反馈。无需先换前端框架，也无需先建设三维大屏。

优先顺序：

1. 纠正坐标、指标、时间与证据语义，确保图斑和结论可信。
2. 统一烟台工作区，让地图、队列、证据和时间同步。
3. 建立可追溯数据底座和两条独立检测通道。
4. 将疑似活动与有效许可核对，形成可解释、可撤回的线索。
5. 接通人工研判、核查、复查，并用独立样本验证。
6. 只有规则基线不足且标注数据合格时，才引入深度学习或预测。

产品需要回答六个问题：**哪里变了、何时变的、变成什么、为什么值得核查、哪些依据缺失、下一步由谁做什么。**

### 2.1 先修正的真实性问题

以下源码发现基于本地工作区。页面行为已现场查看，但本次没有对服务器文件逐一做版本比对，也没有重新计算原始卫星影像。

**A. 图斑坐标契约错误，优先级最高。**

- `data/yantai_rs/p07_2023b/patches.geojson` 的 YT-007 首个顶点约为 `[254307.64, 4113850.94]`，不是经纬度。
- `scripts/yantai_change_detect.py:146` 将分析投影下的几何直接写出；该脚本分析 CRS 为 EPSG:32651。
- `app/yantai_api.py:112` 原样返回几何；`web/yantai.js:141` 直接交给 `L.geoJSON`，后者按经纬度解释。
- 因而中心点可以看起来正确，但图斑不能据此认定正确落图。需保留米制分析几何，另生成 RFC 7946 的 WGS84 经纬度展示几何，并做位置、面积、顶点和往返转换检查。不是把 CRS 标签改成 4326 就完成。

**B. “置信度 0.83/0.96”不是经过验证的概率。**

- `scripts/yantai_change_detect.py:144` 的分值由面积、局部 dBSI 和常数构成，上限 0.96；没有概率校准证据。
- `app/yantai_api.py:151` 还直接指定农业簇分值 0.96。
- 应暂时去掉“置信度”称谓，改为“规则评分（未校准）”，优先展示具体触发依据、质量与待核项。未经校准不显示百分比仪表，不称“违法概率”。

**C. 候选面积和指数需要重审计算口径。**

- `scripts/yantai_change_detect.py:125` 矢量化没有限定前景值 1；满足面积条件的背景连通区也可能进入候选。
- 同文件第 135 行附近用质心邻域近似图斑统计，不能称为整图斑均值；不规则或凹多边形尤其需注意。
- 后续应对前景做掩膜矢量化，在真实图斑内统计有效像元，并由仿射变换计算像元面积。重算前，43 个候选、24.0 ha、0.54 ha 都只能作为已有记录，不能称本次独立验证的结果。

**D. 三年变化不能称近期新发生。**

- 当前主要比较 2023-11-02 与 2026-11-11，只能说明该区间内存在差异。
- 2025 至 2026 年旧阈值未检出，不能证明没有活动，也不能据此精确定位全部变化发生年份。
- 农田/温室簇只有日期未知底图支持，应标“倾向农业/清表，待时相核实”，不能直接成为已确认非采掘负样本。

**E. 检查时间和业务状态不够可靠。**

- `app/yantai_api.py:241` 在没有真实检查记录时用当前时间填充；`check()` 在第 336 行附近只更新内存时间和计数。
- `review()` 在第 319 行使用可选用户，未在该处理器强制业务角色；站点门禁不等于业务授权。这里是源码层风险，不代表本次证实公网可匿名写入。
- 研判 JSON 按事件覆盖旧意见；`_apply_review()` 只改流程状态，活动标签可能继续显示旧判断。需改为版本化意见和明确的生效规则。

**F. 观测物理意义必须保持正确。**

- 当前陆地通道排除了水体；不能直接套用于采砂。
- 固定 `DN * 0.0001 - 0.1`、计算前截断反射率，须改为逐产品元数据驱动，并区分显示拉伸与物理计算。
- SWIR 原生 20 m，重采样到 10 m 不会增加真实细节。
- 原方案指出 `sltd.geo.tif` 是对流层延迟，不是累计位移。相关旧位移结论必须隔离；本次未独立重算该专题，不能延用为地下开采证据。

## 3. 目标界面：提高信息表达，不增加装饰负担

### 3.1 桌面工作区

点击“烟台预警”后，进入独立的烟台工作区；仍使用现有壳、登录和地图能力。原研究区保留返回入口，不改原业务逻辑。`/yantai` 应能直达并恢复专题状态，而不是仅在旧仪表盘上叠浮窗。

```text
烟台预警 | 采矿 / 河道 | 区县与时间 | 数据覆盖、最近有效观测、任务状态
事件队列         烟台地图 / 同步前后影像                 研判详情
优先级与原因     图斑、许可、工程、缺口                 事实、疑点、依据
观测时间与质量   图层与测量、当前对象定位               许可匹配、补查任务
处置进度         逐景时间轴、面积/指数/水位联动图         历史意见和核查结果
```

- 1920 px 宽时，队列建议 280–300 px，详情 340–380 px，其余给地图；1366 px 时缩为约 240/320 px，保留中心可用宽度。
- 影像精查模式可收起队列，地图/对比影像占宽度至少 65%。不是把完整影像继续挤进右栏。
- 低于适宜三栏的宽度时切为双栏或单视图。375 px 手机上采用“地图、队列、详情”三视图切换；详情前后图可上下排列并同步缩放。
- 同一选择状态贯穿列表、图斑、时间轴和详情。返回队列后保留筛选、位置和滚动，不重复找点。
- 业务正文建议 14–16 px，辅助标签不低于 12 px；手机触控目标至少 44×44 px。图像保持比例，不用 `object-fit: cover` 裁掉证据。

### 3.2 六项核心可视化

| 视图 | 具体怎么做 | 用户得到什么 |
|---|---|---|
| 同步影像精查 | 单地图卷帘、双图联动、手动闪烁切换三选一；同范围、同倍率、同拉伸参数；每幅标日期/传感器/分辨率/有效率 | 看清具体哪里新增开挖，而非对着两张缩略图猜 |
| 对象变化时间轴 | 保存逐景观测，标有效/遮挡/缺景；点击日期同步影像、图斑、指标；显示最后未见与首次出现之间的时间区间 | 区分历史累积、近期新增、持续扩张和无法判断 |
| 许可与活动叠加 | 实际变化面、正式许可面、工程面分层；历史许可随事件时间切换；误差带单独描画 | 看清疑似冲突位置、依据日期和定位不确定性 |
| 证据解释面板 | 分列已观察事实、支持因素、反向解释、缺失依据；每项链接产品/日期/处理版本 | 研判者能解释“为何提示”，也能看到为什么可能是误报 |
| 河段时空矩阵 | 横轴观测日、纵轴正式河段编号或里程；格内区分扰动类型和无观测；点击联动该段影像与水位 | 快速找出同一河段连续扰动，或洪水后大范围共同变化 |
| 覆盖与处置视图 | 按矿点、河段长度、区域面积分别统计有效覆盖；显示观测年龄、缺口原因、待核和逾期队列 | 明确哪里真正看过，以及哪些线索等待行动 |

面积曲线显示绝对变化与基线范围，指数曲线显示历史同季参考带；无有效观测处断线，不填 0、不跨云期画连续趋势。颜色尺度和单位固定，前后影像不各自自动调色制造假变化。精查图显示原始像元尺度；放大不称为分辨率提升。

地图视觉以真实影像为主。普通资源用形状区分类别，优先级才使用红/琥珀/蓝，Q 缺口用灰色纹理和文字。选中轮廓与风险颜色分离。背景以白、浅灰和中性色为主，保留现有少量青绿色交互色；不铺满深蓝、渐变或发光边框。不用三维柱高、雷达图、流光线表达没有测量依据的风险。

### 3.3 一条事件应如何表达

P07 首屏建议表达为：

> P07 坑缘扰动待核。记录面积约 0.54 ha，待规范重算。当前证据为 2023-11-02 至 2026-11-11 两期差异；尚不能定位近期起始时间。现有规则表现为裸地指标上升、植被指标下降。许可和现场材料未取得。建议补近期有效观测、正式矿权及有日期参考材料。

四类状态固定分开：观测质量、活动判断、合规判断、处置状态。高优先级必须显示理由，不能把“活动可能性高”“影响大”“资料缺失”混成一个数。

### 3.4 界面验收场景

1. 进入烟台后，主图、统计、队列、时间条件全部属于烟台；旧研究区数字不残留。
2. 点击 P07，定位同一对象，图斑与中心点一致；无需关闭详情即可查看前后地理配准影像。

## 4. 遥感分析路线

### 4.1 公共基础：先保证每景可比

步骤：产品发现与分页去重；记录产品和重处理版本；读取 scale/offset 与质量信息；云影、雪、饱和、NoData 检查；配准与网格统一；目标范围有效率统计；输出分析栅格、展示影像和运行清单。

元数据至少包含 `acquired_at / discovered_at / processed_at`、传感器、原生分辨率、CRS、反射率转换、有效像元比例、配准误差、算法版本与输入校验信息。服务器存 UTC，界面统一按 Asia/Shanghai 展示，并标时区。

候选及周边有效率 80% 可作为试点起始门槛，必须另查关键变化边缘，最终由本地样本标定。云边、错配、山影、水位不可比等情况进入质量不足队列。默认可比影像配准误差目标不大于半个分析像元；达不到时降级，不进行精细越界结论。此目标须以控制点与影像条件验证，不代表目前已达到。

### 4.2 露天采矿：从“双时相裸地”升级为“对象级活动过程”

1. 为每个矿点及邻近未知区域建立最近 30–90 天短期基线和过去 2–3 年同季基线，保留每景而不只保留合成图。
2. 用 BSI、NDVI、原始反射率、裸地占比和持续变化生成候选。阈值在本地稳定区、活动区与困难负样本上标定。
3. 形成对象级特征：坑缘推进、新剥离面、堆场变化、道路连接、停闭后再扰动。每项注明是否能被当前分辨率支持。
4. 对农业轮作、果园、温室、道路、施工、复垦等保留替代解释，不用历史地类一票否决新开挖。
5. 常规候选用第二次有效观测或独立的有日期高分/现场材料确认持续性；同景多个指数不算独立证据。高影响且证据充分的候选允许直接人工复核。
6. 输出变化面、面积和误差、首次可见区间、持续性、支持/反向因素、缺失项；同一对象后续观测更新事件，不每天制造新事件。

预期成果：从“BSI 变红”升级为“某对象在某区间发生何种地表变化，证据强弱如何”。仍不直接认定非法。

### 4.3 河道采砂：单独建设水陆联合通道

1. 水利部门先确定 1–2 段试点、正式管理范围和分段编号。按水文与管理单元分段，必要时细分为约 0.5–2 km 单元；不能只按固定长度忽略支流、闸坝和河宽差异。
2. 保留有效水体像元；使用 NDWI/MNDWI、水面/沙洲边界、岸线与裸地变化。SWIR 参与时如实标明 20 m 原生尺度。
3. 将影像与同期水位、降雨、洪水、闸坝调度和季节对齐。比较相近水位条件；没有实测水文时降低结论强度。
4. 组合看沙洲切割、异常坑槽可见迹象、岸边新堆砂、装卸面和新道路。浑浊变化只是辅助，不能单独推断采砂，更不能无本地校准就换算悬沙浓度。
5. 加入上游、下游和相邻自然河段对照，排除共同洪水冲淤、自然退水以及已批准的疏浚/治理工程。
6. 10 m 光学不足以可靠识别的小船、设备和窄河段，直接标能力不足；优先补授权高分或外业，不用图像放大和通用目标检测“补出”细节。
7. 输出河段扰动对象、岸水变化图、水文对比、工程排除状态与补查建议；图像不充分则仅输出观测缺口。

预期成果：形成“河段变化是否异常、能否被水文或合法工程解释”的研判能力，而不是把所有沙洲变化叫采砂。

### 4.4 SAR、高分与 AI 的位置

- Sentinel-1 RTC：仅在同相对轨道、模式、极化、相近入射角和有效足迹条件下比较，核对线性量/dB 与产品类型，处理斑点及地形影响。补充持续地表扰动信息，不替代光学语义、不直接判断违法。InSAR 不作为一期主线。
- 有日期高分影像：用于判明坑缘、堆场、道路、设备等细节；采购前明确成像日期、定位精度、云量、分析及展示授权。未知日期网络底图只用于导航和背景。
- 规则加 scikit-learn：先以本地对象特征建立可解释分类基线，使用空间块和时间留出，报告分类与校准结果。
- Open-CD：作为本地高分变化分割的对照实验，不把建筑变化权重直接当矿山模型。只在独立留出数据上优于规则基线，且人工核查负荷可控时上线。
- TorchGeo：用于规范数据采样、训练和预训练权重实验，不能替代本地数据及标签。
- SamGeo：用于专家辅助圈绘矿坑、堆场、沙洲和标注草稿；所有输出经人工复核。分割出物体不等于知道物体用途，也不等于识别违法。
- 预测：放在后续阶段，仅预测已授权矿点/河段的待核活动风险。必须优于“历史复发频次”等简单基线；不做个人风险画像或自动执法决定。

## 6. 分步实施：怎么做、做成什么、如何验收

以下均是获准后的工作，不是本次执行内容。正式工期以试点范围、数据授权和核查渠道到位为前提。建议 12 周受控试点，部分工作并行；不是对缺数据条件下的交付承诺。

### 第 1 步：冻结口径与修正清单，第 1 周

**怎么做：** 负责人、遥感人员、自然资源和水利联系人共同确认试点对象、能识别的活动、四类状态和发布边界。逐项复核第 2.1 节问题；保留原始记录，不静默覆盖历史结果。将 3 条旧记录注明“历史试点材料”。登记 P07 地名/行政归属在脚本与页面中的差异，以正式边界核对，不沿用未经确认的“莱州/招远”称谓。

**做成什么：** 一份数据字典、一份问题及责任清单、一份当前能力声明；现有数字都能区分“原记录”“已复算”“已核验”。

**验收：** 缺测不填零、查不到许可不称无证、规则分值不称概率；单位、坐标、日期、活动与合规定义经业务签字确认。

### 第 2 步：取得试点数据与授权，第 1–2 周

**怎么做：** 优先选择一个采矿样区及 1–2 个可获得水文与工程资料的河段。向主管部门申请现行及历史采矿权、采砂许可、禁采要求、河道管理范围、疏浚工程、停闭/复工材料；取得行政边界、参考影像及独立现场反馈。为每层记录来源、版本、有效期、坐标、精度、使用范围与负责人。

**做成什么：** `数据目录 + 授权清单 + 缺口台账 + 样区清单`。OSM 独立作为背景层。全市没拿到资料的位置仍可显示，但明确“未纳入有效监测”。

**验收：** 至少一个矿区、一个河段具备活动验证和合规对照资料；否则只开展技术/活动监测试验，不启动疑似违法预警验收计时。

### 第 3 步：修好空间与影像数据底座，第 2–4 周

**怎么做：** 统一分析投影与展示经纬度转换；检查正式 CGCS2000 等数据的真实坐标定义，不能猜测。烟台跨分带范围按实际位置选择适宜米制投影，面积汇总使用一致的面积口径。纠正前景矢量化与图斑统计；逐产品反射率、掩膜、配准校验；输出 COG 与质量栅格，保留原始分辨率信息。

**做成什么：** 带来源的正式图层；正确落图的变化面；能复算的影像、质量掩膜和 `run_manifest`；可供精查的地理配准瓦片。

**验收：** 图斑顶点落在声明范围内，中心与几何关系合理；空前景不产出背景多边形；面积与前景像元按同口径一致；所有发布事件可追溯至产品和处理版本。旧 P07 数值重算后若变化，保留新旧差异及原因。

### 第 4 步：完成统一研判界面，第 3–5 周

**怎么做：** 先以真实试点材料制作低保真工作流并由研判人员确认，再改造专题路由、主图范围、队列和详情。加入同步卷帘/双图、对象高亮、全幅和对象上下文切换；列表按观测时间、质量、活动、合规、处置筛选。开发期间真实缺数据就显示缺口，不填模拟成效数字。

**做成什么：** 可用的烟台研判工作区；P07 和农业簇各自定位及裁切，不再共用整幅图冒充事件近景；手机可以独立看图和完成研判。

**验收：** 第 3.4 节场景全部通过。建议找 3 名实际研判人员，用固定案例测试“定位、比较、解释、提出补查任务”；记录任务完成率和耗时，不能只凭截图宣布易用。

### 第 5 步：接通逐景目录与持久化处理，第 4–6 周

**怎么做：** 复用 `imagery_watch.py` 的上游访问与首次基线思路，但把烟台 AOI、分页和任务持久化独立配置；现有单页新影像发现不能当异常识别。按产品、AOI、算法版本生成幂等任务，保存成功、拒绝、失败及重试状态。目录检查、有效观测和处理完成使用三个不同时间。

**做成什么：** 可恢复的 `发现—质检—处理—候选—研判` 任务链；每个对象有观测台账；断网和云遮挡可见。

**验收：** 重启不丢任务；同景重复发现不重复生成；重处理版本不乱发新通知；历史回放不会形成“刚发生”告警；上游失败显示失败而非零异常。可先将目录检查间隔设为 6 小时，再按配额和需求调整，但不承诺每 6 小时有新卫星影像。

### 第 6 步：形成采矿对象级监测，第 5–6 周

**怎么做：** 按第 4.2 节建立双基线、对象特征和变化持续性，专门处理已知农业误报。将规则与分值解释写入版本化配置；对矿区外随机网格同样抽查，避免只发现已知矿。

**做成什么：** 矿坑扩张、新扰动、疑似复采等活动候选；每条有变化面、时段、面积、证据和反向解释。

**验收：** 真实变化与农田/果园/道路等困难样本分层评估；缺少独立时相的 P07 不得变成当前持续采矿结论。达不到标准就保留人工辅助，不扩到全市。

### 第 7 步：形成河道独立监测，第 5–7 周

**怎么做：** 按第 4.3 节实现水陆质量掩膜、岸滩变化、水位对照和工程排除；同步建设河段时空矩阵。对窄河段建立补充观测任务，不强行用 10 m 输出船只或设备数量。

**做成什么：** 河段扰动与水文/工程解释报告；真正有观测依据的候选，或明确的能力缺口。

**验收：** 单独测试洪水冲淤、退水露滩、合法疏浚、普通岸边施工与已核实采砂；不能用采矿精度替代采砂精度。没有目标活动真值时，交付“待验证通道”，不宣称已达到采砂识别率。

### 第 8 步：许可时态匹配与线索分级，第 6–8 周

**怎么做：** 按活动可见区间关联当时有效的许可、禁采和工程版本；区间跨越许可变更时逐段说明，不强行选一个日期。变化面与边界之间引入定位、配准、边界精度形成的不确定区域，误差不可随意设成固定法律距离。缺正式边界或仅落在误差带时标待测。

**做成什么：** “支持何种疑似冲突、依据哪份文件、哪里不确定”的匹配结果。P1/P2/P3 表示业务优先级，Q 表示质量/资料缺口；等级规则经业务确认。

**验收：** 许可缺失、过期台账、合法工程、变更时段、边界附近和资料冲突案例都能正确降级。只由有权限人员根据正式依据录入确认结论，模型不自动写“违法”。

### 第 9 步：接通核查、审计与运维，第 7–8 周

**怎么做：** 对接现有案件工作台和移动核查，不另建一套案件系统。研判意见追加保存，记录人、依据、时间与生效版本；区分“确认活动”与“确认违法”。同一事件多期更新、拆分合并、排除、重新打开均留历史。通知采用持久化发送记录和幂等键。

**做成什么：** 从候选到补材料、人工复核、属地任务、结果反馈及后续复查的完整闭环；授权访问和备份恢复机制。

**验收：** 无角色用户不能写研判；修改不能抹掉旧意见；同一事件不重复派单；排除和证据不足都能正常关闭或转观察；回写结论进入样本库前再次审核。

### 第 10 步：四周影子运行与决定是否上线，第 9–12 周

**怎么做：** 连续运行，所有高优先级先人工审核；分层抽查未告警区域；分别记录采矿、采砂、可观测、不可观测、待核比例和人工耗时。冻结空间/时间留出集，不用验收集反复调阈值。

**做成什么：** 一份可审查的效果、时效、覆盖、核查负荷及失败报告；明确“允许在哪些样区做何种级别的运行”。

**验收：** 采用第 8 节门槛。数据不足则延长验证；达标也只有限上线。之后至少再做 8–12 周扩大范围的前瞻运行及跨季节验证，才决定全市推广。

### 第 11 步：有条件引入模型与预测，试点通过后

**怎么做：** 先测本地标注是否足以支持模型，使用 Open-CD 或 TorchGeo 做一条可回退的离线试验；SamGeo 只辅助标注。与规则基线比较效果、成本、误报负荷、跨区/跨季性能。预测需具备连续、可靠、无泄漏标签，再单独立项。

**做成什么：** 有证据证明值得采用的模型，或明确保留规则路线的结论；不是必须交付一个大模型。

**验收：** 独立留出集提升有统计依据，资源与维护可承受，数据/权重授权明确；上线可切回上一版本。未优于简单基线则不采用。

## 7. 技术实施边界与人员

### 7.1 最小架构

```text
授权资料与卫星目录
持久化产品/观测/任务台账
公共质检 + 采矿通道 + 河道通道

```

小试点可继续用 SQLite，采用明确的单写入策略、事务和备份；栅格不塞入数据库。跨进程、多写入或复杂空间查询压测显示瓶颈时，再评估 PostGIS，不先做全栈迁移。处理任务不放在用户请求里同步运行，也不只放进程内存。

核心实体建议为 `scene / observation / analysis_run / activity_object / event / permit_version / review / task_link`。事件引用观测和处理产物，不在 API 中手写三个样例作为事实源。接口统一返回数据时间、版本、质量、权限和缺口原因。

候选、活动对象、业务事件是不同层：同一对象多期候选可以归并为一个事件，但必须保留拆分/合并与再次活动的沿革。不得只按“中心点近”就合并相邻不同作业。

### 7.3 安全与成本

- 当前检查地址使用 HTTP。正式内部业务上线前必须提供 HTTPS、角色授权、访问审计；建议完成传输安全配置后更换演示口令。本次未改凭据。
- TiTiler 仅通过授权 `asset_id` 访问白名单资产，不向外开放任意 `url` 读取；防止越权、服务端请求伪造和签名地址泄露。
- 精确矿权、许可附件、现场资料和人员信息不得上传未经批准的云模型、公开仓库或第三方制图服务。代码、模型和数据许可证分别检查。
- 至少明确 1 名遥感/GIS 主责、1 名系统开发主责，另有自然资源、水利和属地核查的固定投入。界面评审必须有实际使用人员。
- 首期先用 CPU 窗口读取与缓存。可按 8–16 核、32–64 GB 内存和约 2 TB 可用 SSD 做样区压测起点，不承诺这是全市配置；GPU 按模型试验再评估。
- 预算先核算数据授权、高分复核、外业、人力与运维；不无报价给出总价。用每景处理耗时、存储增长和每周核查量决定扩容。

## 8. 验收指标与停止条件

以下全部是建议目标，当前未测得。采矿与采砂分别报告，不合并掩盖差异。

| 维度 | 目标或判定 |
|---|---|
| 来源 | 发布事件 100% 关联产品、时间、处理版本和合规依据/缺口 |
| 语义安全 | 缺测标正常、查无公开许可即无证、模型直接确认违法：0 次 |
| 空间正确性 | 展示几何经纬度合法且落在样区；面积和坐标抽检通过，近边界有误差说明 |
| 高优先级活动命中 | 初始争取 ≥80%；报告 95% 置信区间及未核验比例，不称违法准确率 |
| 可观测活动召回 | 初始争取 ≥70%；真值独立，另报不可观测事件，不能只抽查告警 |
| 标签 | 倾向性解释、未知、未核验不当确定正/负；样本按对象、空间块和时间隔离 |
| 处理时效 | 从可用产品被发现到处理完成 P95 ≤6 小时；另报过境、发布和总发现延迟 |
| 通知时效 | 从人工/规则允许发布到成功通知 P95 ≤15 分钟 |
| 观测覆盖 | 按已纳入服务的全部对象/河段计算分母；展示每个缺口，而非只统计成功处理区域 |
| 人工负荷 | 不超过双方约定的日/周核查容量；可先按每人每天约 10 条详细研判测算 |
| 页面性能 | 指定测试机/网络下，首屏可操作建议 ≤3 秒；选择事件后缓存定位/详情 ≤1 秒；冷影像加载单独报告 |
| 恢复能力 | 重启、断网、上游失败、重复产品、通知重试、备份恢复、权限拒绝演练通过 |

样本可先争取每通道至少 30 个独立已核实目标活动事件、100 个非目标事件作为初步诊断起点；不能因此声称统计精度充分。没有独立漏报抽样时，不报告总体召回。无法及时核查的事件，必须公开其数量和可能的选择偏差。

停止或降级条件：许可授权不明、位置误差无法控制、关键处理不可复算、误报长期超过核查容量、外业反馈中断、重大数据泄露风险。此时可保留受控活动观察，不继续输出自动合规预警。

## 9. 最终应交付的结果

第一阶段不是“更漂亮的试点浮窗”，而是以下六项可验收成果：

1. **统一烟台研判工作区**：主图、队列、证据、时间和手机端一致。
2. **可信数据目录**：权威与公开背景分开，许可有时效，缺口可见。
3. **两条可复算分析通道**：采矿关注对象持续变化；采砂关注水陆变化及水文/工程解释。
4. **可解释预警记录**：活动与合规分开，明确为什么提示、哪里不确定、下一步补什么。
5. **可追溯业务闭环**：权限、研判、派发、现场反馈、复查与撤回都有历史。
6. **真实效果报告**：覆盖、误报、漏报、时间、人工成本和不适用范围一起报告。

对外能力名称分阶段使用：只有试点影像时为“遥感监测试验”；有活动检测但缺许可时为“疑似采掘活动监测”；正式许可、观测、审核与核查闭环齐备且验收通过后，才在指定样区称“疑似违法线索预警”。
