# 警务遥感平台 V2 · 落地方案

> 版本：2026-11-09  
> 定位：从“遥感态势大屏”升级为“生态警务线索处置平台”，再扩展为可复用的“警务时空智能底座”。  
> 原则：**不伪造数据、不替代法定鉴定、不承诺预测精度**；所有推断都标注来源、口径与边界。

---

## 0. 一页结论

### 0.1 现在有什么

- 真实公开遥感与地理数据：MPC Sentinel-2/Landsat、MODIS NDVI、AWS DEM、OpenStreetMap、WorldPop、Open-Meteo。
- 双分数语义分离：**历史核查优先级**（AHP，回答“先查哪”）与**当前危险指数**（自然因子×人口暴露，回答“现在多危险”），不混为一个“预警分”。
- 案件工作台：登录/四角色/案件/任务/证据 SHA-256/复核/归档/审计/二维码/PDF 报告/离线核查包。
- 新影像到访监听：只报“有新影像”，不冒充变化检测。
- 可运行的 Docker、Tailscale Funnel 公网入口、章丘与青山两个研究区。

### 0.2 缺什么（决定“能不能落地”）

| 缺口 | 后果 | 本次是否补齐 |
|---|---|---|
| 民警到现场后没有移动端 | 证据靠微信/纸质，回办公室再补 | ✅ 移动核查 H5 + 到场码 + 离线队列 |
| 证据只有单文件哈希，没有链 | 无法证明“有没有被删/被换” | ✅ HMAC 证据链 + 深度校验 |
| 只有直线距离，没有车行时间 | 指挥员不知道“多久能到” | ✅ OSRM 车行到达圈 + 诚实降级 |
| 没有无人机航线 | 大范围核查靠脚走 | ✅ DEM 跟随航线 + KML/CSV |
| 法条与证据清单靠个人经验 | 现场漏取证、定性不准 | ✅ 法条/证据清单助手（草稿，需法制复核） |
| 模型效果没有闭环 | 永远说不清“准不准” | ✅ 核查结论回填 + 评测台 |
| 影像到访与案件脱节 | 看完影像就结束 | ✅ 新影像一键建案 + 覆盖高发点提示 |

### 0.3 本次交付的新能力

1. **移动核查端** `/m/checkin?token=...`：扫码到场、GPS、拍照、离线暂存、联网补传、幂等去重。
2. **证据保管链**：每条证据进入 HMAC-SHA256 链，案件页显示“链完整/异常”，支持深度校验文件字节。
3. **到达圈**：车行距离/时间/路线，公共 OSRM 失败时降级为直线估算并明确标注。
4. **无人机航线**：矩形测区、DEM 地形跟随、绝对高度、航点数/里程/时长/电池估算，导出 KML/CSV。
5. **法条助手**：17 类风险 + 通用执法，按灾种/关键词检索法条、证据清单、处置步骤。
6. **评测台**：把现场核查结论回填为 `confirmed/excluded/inconclusive`，输出核查命中率与覆盖率，明确“不是预报精度”。
7. **工具页** `/tools`：把上述能力集中为“作战工具”，不再堆在大屏上。
8. **工程加固**：登录限流、安全响应头、健康检查、`.env.example`、冒烟测试。

## 1. 五种可扩展应用方向

按“与现有能力复用度、数据可得性、合规风险、交付周期”排序，推荐顺序：**① 生态警务 → ② 灾害应急 → ⑤ 城市治理 → ④ 线状巡查 → ③ 大型活动安保**。

### 方向一：生态警务全链条（主线，建议先做深）

| 项 | 内容 |
|---|---|
| 目标用户 | 食药环侦、森林公安、保护区派出所、河湖长办、自然资源执法 |
| 核心痛点 | 线索来源散（卫星、举报、巡查、视频），无编号、无期限、无证据标准；行政执法与刑事司法衔接难 |
| 复用模块 | 双分数、案件闭环、移动核查、法条助手、证据链、影像监听、离线包 |
| 新增模块 | 多源线索池、行政/刑事分流、移送文书、案件串并、与警综/行政执法平台对接 |
| 关键数据 | MPC/Landsat、国土变更调查、林地一张图、排污许可、行政处罚公开信息 |
| GitHub 参考 | Camunda 4.3k（流程编排）、Temporal 24k（长事务）、ODK Collect 801/KoboToolbox 189（移动采集）、STAC-fastapi 327（影像目录）、MinIO 61k（证据对象存储，AGPL 注意） |
| 交付周期 | 8–12 周（在现有基础上） |
| 商业模式 | 区县/地市项目制 + 年度运维 + 专题数据服务 |
| 合规要点 | 行政处罚法、行刑衔接规定、数据分类分级、证据原件保管 |

**落地动作**：先把“线索池”做出来——卫星、举报、巡查、视频四类线索统一编号；再做“分流”——轻微违法走行政、涉嫌犯罪走刑事；最后做“移送”——生成移送书、证据清单、法制审核记录。

### 方向二：灾害应急与防汛防火

| 项 | 内容 |
|---|---|
| 目标用户 | 情指中心、应急管理局、消防救援、水利、林草 |
| 核心痛点 | 灾前不知道先撤谁，灾中不知道路通不通，灾后不知道损失多大 |
| 复用模块 | 当前危险指数、DEM、路网、人口、警力点位、到达圈、无人机航线 |
| 新增模块 | 气象预警接入、水文站/水库、火点/烟点、简化淹没模拟、避难场所、疏散路线、灾损核查任务 |
| 关键数据 | 气象预警、水文站、水库汛限水位、消防/避难场所、历史灾情 |
| GitHub 参考 | Cesium 15.9k（三维）、Prithvi-EO-2.0 338 / Clay 625（遥感基础模型）、OpenDroneMap（灾后正射，未抓星数）、OR-Tools 14.3k（调度） |
| 交付周期 | 12–16 周 |

### 2.1 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 移动端 | 原生 PWA + IndexedDB，不上 React | 现有前端是原生 JS；离线包体积小；无构建链，内网易部署 |
| 到场授权 | 案件级短期到场码（哈希存储） | 民警不一定有账号；扫码即用；可过期/可吊销/可限次 |
| 证据链 | HMAC-SHA256 链 + 案件链头锚定 | 纯 SHA-256 链无法发现“删除后重算”；HMAC 密钥在库外 |
| 到达圈 | OSRM 公共实例 + 本地缓存 + 降级 | 快速可用；生产切自建 Valhalla/OSRM 只改一个 URL |
| 地形 | AWS Terrarium DEM（z13） | 免密钥、全球可用、够航线规划用；不用于测绘级高程 |
| 法条 | 本地 JSON 知识库 + 人工复核标记 | 不调用大模型，避免编造法条；可离线；可审计版本 |
| 评测 | 只算“已核查样本命中率”，不算 AUC | 没有负样本，算 AUC 是伪科学 |
| 工具页 | 独立 `/tools`，不塞进大屏 | 大屏是“看”，工具页是“算”；降低首页复杂度 |

## 3. 数据模型（新增表）

```sql
-- 到场码：只存哈希，明文只在生成时返回一次
CREATE TABLE arrival_tokens (
  token_hash TEXT PRIMARY KEY,
  token_hint TEXT,              -- 末 4 位，便于识别
  case_id TEXT NOT NULL,
  created_by INTEGER,
  created_by_name TEXT,
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  max_uses INTEGER NOT NULL DEFAULT 0,   -- 0 = 不限次
  uses INTEGER NOT NULL DEFAULT 0,
  revoked INTEGER NOT NULL DEFAULT 0,
  note TEXT
);

-- 到场记录：一次提交（可含多张照片）
CREATE TABLE checkins (
  id TEXT PRIMARY KEY,          -- 客户端 UUID，幂等
  case_id TEXT NOT NULL,
  token_hash TEXT,
  task_id TEXT,
  actor_name TEXT,
  lon REAL, lat REAL, accuracy REAL,
  captured_at TEXT,
  note TEXT,
  device TEXT,
  source TEXT,                  -- mobile_web / offline_sync
  evidence_ids TEXT,            -- JSON 数组
  created_at TEXT NOT NULL
);

-- 案件证据链头：用于发现“删除/替换后重算”
CREATE TABLE case_chains (
  case_id TEXT PRIMARY KEY,
  head TEXT NOT NULL,
  count INTEGER NOT NULL,
  updated_at TEXT NOT NULL,
  sealed_at TEXT,
  backfilled INTEGER NOT NULL DEFAULT 0
);

-- 现场核查结论：评测的数据飞轮
CREATE TABLE verifications (
  id TEXT PRIMARY KEY,
  case_id TEXT NOT NULL UNIQUE,
  verdict TEXT NOT NULL CHECK(verdict IN ('confirmed','excluded','inconclusive')),
  note TEXT,
  evidence_id TEXT,
  verified_by INTEGER,
  verified_by_name TEXT,
  verified_at TEXT NOT NULL
);
```

索引：`checkins(case_id, created_at)`、`arrival_tokens(case_id)`、`verifications(verdict)`。

## 5. 关键技术实现

### 5.1 证据链

```text
prev = "GENESIS"
for ev in evidence ordered by (created_at, id):
    payload = f"{prev}|{ev.id}|{ev.sha256}|{ev.size}|{ev.captured_at}|{ev.created_at}"
    link = HMAC-SHA256(key, payload)
    prev = link
head = prev
```

- 密钥：`POLICE_EVIDENCE_KEY` 或 `instance/.evidence_key`（首次自动生成，32 字节）。
- 每次上传后更新 `case_chains.head/count`。
- 校验时重算链，与库中链头/条数比对；`deep=1` 再重算文件字节。
- **能发现**：文件被替换、证据行被删除/新增、顺序被改。
- **不能发现**：拥有服务器密钥和数据库写权限的人伪造整条链；也不能证明拍摄时间/地点真实。
- 报告中必须写明：“哈希链证明文件与记录的一致性，不替代法定电子数据鉴定。”

### 5.2 移动端离线

- Service Worker 缓存 `checkin.html/js/css` 与警徽图标，断网可打开。
- 照片在浏览器端压缩到最长边 1600px、JPEG 0.85，再计算 SHA-256。
- 提交记录写入 IndexedDB：`{client_id, token, fields, blobs[], created_at}`。
- `online` 事件或“立即同步”按钮触发上传；成功后删除本地记录。
- 幂等：`client_id` 作为 `checkins.id`；重复提交返回已有记录，不重复入库。
- 原始照片哈希在压缩前计算并随表单上报，标注“客户端自报，服务端不可验证”；服务端校验的是压缩后字节的哈希。

### 5.3 到达圈

- 主路径：`router.project-osrm.org/route/v1/driving/{lon1},{lat1};{lon2},{lat2}?overview=full&geometries=geojson`。
- 缓存：`data/cache/routes/{md5}.json`，7 天。
- 降级：直线距离 × 1.35 绕行系数，速度 45 km/h；返回 `provider="estimate"`、`confidence="low"`，前端黄色提示。
- 生产：自建 OSRM/Valhalla，或购买商用路径规划；公共实例只用于演示。

### 5.4 无人机航线

- 输入：中心点、半径、相对地面高度、重叠率、相机水平 FOV、速度。
- 地面幅宽 `W = 2 × h × tan(FOV/2)`；航线间距 `W × (1 - overlap)`。
- 边界往返（boustrophedon），航点上限 400；超限自动加大间距并回报“重叠率已降低”。
- DEM：AWS Terrarium `z=13`，高程 `R×256 + G + B/256 - 32768`；每点取中心 + 四邻域最大值，再加安全余量。
- 输出：绝对高度 KML（`altitudeMode=absolute`）、CSV（序号/经纬度/地面高程/绝对高度/AGL）、GeoJSON。
- 明确：不是航测级航带设计，不替代空域审批、不保证避障；起飞前必须现场校核。

### 5.5 法条助手

- 本地 JSON，按 `hazard` 映射；每条含法条摘要、证据清单、处置步骤、复核状态。
- 检索：标题/关键词/法条/证据加权打分，纯本地，无大模型。
- 所有条目 `review_status="draft_requires_legal_review"`，页面顶部固定免责声明。
- 条号以现行有效文本为准；正式使用前由法制部门复核并锁定版本。

### 5.6 评测台

- 数据：案件 + 现场核查结论 + 历史样本（83 个，弱标签）。
- 指标：
  - 覆盖率 = 有结论案件 / 全部案件。
  - 核查命中率 = confirmed / (confirmed + excluded)；`inconclusive` 单列，不混入分母。
  - 分灾种统计。
  - 历史样本回溯覆盖率（沿用 `samples.py`，明确不是预报精度）。
- 明确：没有“已确认无灾”的负样本，不能算 precision/recall/AUC；样本量小时只做描述统计。

## 8. 风险与边界

| 风险 | 说明 | 应对 |
|---|---|---|
| 把“分数”当“预警” | 双分数易被误读 | 页面固定口径说明；报告写明“不是官方预警” |
| 把“新影像”当“新警情” | 影像到访≠变化 | 只报“到访”，建案需人工确认 |
| 公共 OSRM 不稳定 | 演示服务器无 SLA | 缓存 + 降级 + 生产自建 |
| DEM 精度不足 | Terrarium 约 15–30m 网格 | 标注“航线规划参考”，现场校核 |
| 法条过期/条号变化 | 法律修订 | 法制复核 + 版本号 + 免责声明 |
| 样本偏差 | 只有正样本、历史检测结果非真值 | 只算核查命中率；不宣称预报精度 |
| 移动端证据真实性 | GPS 可伪造、照片可翻拍 | 记录设备时间/坐标/精度，标注“自报”；关键案件仍需现场笔录 |
| 密钥丢失 | 证据链无法验证 | 备份密钥；报告注明链起点时间 |
