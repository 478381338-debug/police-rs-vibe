## 1. 车行到达圈（2026-11-09）

### 1.1 目标

给定案件点和车行时间，给出“车行可达范围”的近似轮廓，并满足三个约束：

1. 不能把直线距离冒充车行距离；
2. OSRM 把偏远点吸附到远处道路时，必须发现并说明；
3. 外部服务不可用时，明确降级，不伪造成功。

### 1.2 设计决策

| 决策 | 原因 |
|---|---|
| 用 OSRM `table` 做放射采样，不用“直线半径”直接当结果 | 公共 OSRM 没有 isochrone 接口；采样+插值是可解释的近似 |
| 36 个方位 × 10 个半径，每批最多 99 个目的地 | 公共实例 `table` 上限约 100 个坐标；4 批并行，2–3 秒可返回 |
| 校验中心点和采样点的道路吸附距离 | 偏远林区会把点吸附到几公里外，直接画会“看起来很近、实际起点在别处” |
| 有效方位不足 12/36 就整体降级 | 少量方位成圈会产生严重偏差，不如明确给直线估算 |
| 直线降级按 45 km/h、绕行系数 1.35 | 只用于量级判断；在响应和 UI 中都写明不是路网结果 |
| 正常结果缓存 7 天，降级结果缓存 10 分钟 | 避免重复请求公共 OSRM；也避免把临时网络故障固化一周 |
| 返回 GeoJSON Feature，而不是只返回 PNG | 可直接进 GIS/报告，也便于后续在 Leaflet/MapLibre 上叠加 |

## 2. 无人机核查航线（2026-11-09）

### 2.1 目标

按案件坐标生成可导入无人机地面站/ GIS 的核查航线，并满足：

1. 航点高度跟随 DEM，而不是固定海拔；
2. 同时输出 KML（绝对高度）和 CSV（逐点高程），便于人工复核；
3. DEM 缺失、航点过多时明确降级或拒绝，不伪造“适航”结果；
4. 页面明确写出未接入禁飞区、空域审批、风场和电池模型。

### 2.2 设计决策

| 决策 | 原因 |
|---|---|
| 提供“往复扫描”和“环绕”两种模式 | 面状盗采/火迹适合往复，小范围重点点位适合环绕 |
| 先按米制局部坐标生成，再换算经纬度 | 距离、间距、方向可直接按米控制；经度用 `cos(lat)` 修正 |
| 航线按 `sample_m` 加密 | 航点太稀无法跟随地形，太密超过地面站上限 |
| 高度 = DEM 地形 + 相对地面高度 | 输出绝对高度，KML 用 `altitudeMode=absolute` |
| 单次最多 800 个航点（可配） | 防止默认参数在 5 km 范围生成数万点；超限报错而不是截断 |
| 航时只按距离/速度/转弯估算 | 不伪造风场、爬升、电池余量；页面单独说明 |
| 不生成航点动作（拍照/云台） | 不同机型协议差异大，先保证几何航线可用 |

## 3. 法条与证据清单检索助手（2026-11-09）

### 3.1 目标

把“现场该看什么、该固定什么、可能涉及哪条法”做成可检索的办案辅助，而不是让模型自由生成法条。输出必须带草稿状态、免责声明和人工法制审核提示。

### 3.2 设计决策

- 使用本地 JSON 知识库，不接在线法律数据库，避免网络依赖和版本漂移。
- 17 条条目全部标记 `review_status=draft_requires_legal_review`；摘要只用于提示取证方向，不给出构罪、处罚或移送结论。
- 检索按“标题 8 分、关键词 6 分、法律名称 4 分、条款 3 分、摘要 2 分”排序；支持关键词和灾种两个过滤条件。
- 案件清单先按 `data_snapshot.properties.dominant_hazard` / `dominant_class` 识别灾种，再叠加通用条目（刑诉法第 50 条、第 128/141 条、行政处罚法第 27 条）。
- 灾种别名：`fire→fire_risk`、`flood→flood_risk`、`drought→drought_risk`、`geohazard→geohazard_risk`。
- 去重后的取证清单按原文完全一致去重，并保留来源条目 ID；不做语义合并，避免把不同证据要求误合并。
- 自然风险类灾种没有直接对应刑法条文时，明确提示“草稿库暂无该灾种直接对应条文，以下为通用取证与移送清单”，不硬套罪名。

### 8.3 访问口令失败锁定

新增环境变量：

```bash
POLICE_GATE_MAX_FAILS=5        # 窗口内允许的失败次数
POLICE_GATE_LOCK_MINUTES=15    # 达到次数后的锁定时间
```

- 计数键为“客户端地址 + 账号”，优先取 `X-Forwarded-For` 首个地址，否则取连接地址。
- 窗口内第 5 次失败起返回 429，页面显示“尝试次数过多，请 N 分钟后再试”，并带 `Retry-After`；锁定期间即使口令正确也拒绝，到期自动解锁。
- 登录成功清零该键；计数表超过 4096 个键时清理过期项。
- 计数保存在进程内存，当前部署为 `--workers 1`；扩到多 worker 时需换 Redis 或网关限流。

## 9. 法条检索：从关键词推断主要法条（2026-11-11）

### 9.1 问题与根因

在工作台“法条与取证清单”输入“占用农田地”后，列表仍停留在案件灾种清单；即使触发检索，首条也是刑法第三百三十八条污染环境罪，而不是第三百四十二条非法占用农用地罪。排查到三个独立原因：

- 前端只给“检索”按钮绑定了 `click`，输入框没有 Enter 或 `input` 监听，打字后不会自动检索。
- 后端 `_score` 只做整串精确子串匹配；知识库写的是“非法占用农用地/耕地”，没有“农田地”，因此得分为 0。
- 案件清单 `case_checklist` 按条目 id 排序，非法采矿灾种下 338 排在 343 前，主次颠倒。

### 9.2 后端改动（app/legal.py）

- `HAZARD_PRIMARY`：灾种到主条目的映射。采矿/矿山破坏→343，倾倒/水体异常→338，违建/裸土/道路侵入/湿地→342，植被退化/火烧→345。
- `PRIMARY_RULES`：十条“语义规则→条目+灾种”映射，覆盖农用地占用、矿产资源开采、污染环境、固体废物、水产品捕捞、野生动物、重点保护植物、林木采伐、毁林开垦、自然保护区。
- `SYNONYMS`：把“农田/农田地/农地”归一到“农用地、耕地”，并补充占用、采砂、排污、砍树等口语词。
- `_similarity`：双字 Dice 相似度；`_score` 先做同义词扩展和规则加权，再按 heading 8 / keywords 6 / law 3 / article 3 / summary 2 的字段权重计分，相似度 ≥0.34 时加 `int(sim×24)` 兜底召回。
- `search()` 新增 `inferred_hazard`、`inferred_hazard_label`、`primary`（仅 top 分 ≥8 时给出）和零命中时的 `suggestions`；每条结果带 `score`、`match_reason`。
- `case_checklist()` 按 `HAZARD_PRIMARY` 把主条目置顶，并返回 `primary`，`match_reason` 写明“按案件灾种推荐”。

### 9.3 前端改动（web/workspace.js、样式）

### 10.3 变化检测

在 512×256 上计算四类特征并归一化加权：

`score = 0.45 × 纹理 + 0.25 × 高通 + 0.20 × 色彩 + 0.10 × ExG`

- 阈值取 `q=0.93`，经开运算（1）和膨胀（2），最小连通域 150px。
- 只保留 `delta_lum > 0.03` 的新增扰动；`delta_lum ≤ 0.03` 计为光照/物候疑似误报并抑制。
- 2023 影像整体偏亮、2025 偏暗，因此用亮度变化方向过滤“整体变暗”造成的伪变化。

## 10.9 6G×AI 网络感知编排（2026-11-11）

### 目标与边界

- 解决“6G 与 AI 各展示各的”问题：把 6G 切片、可用带宽、时延预算作为 AI 推理编排的输入，而不是页面上的两个并排面板。
- 6G 指标仍为数字孪生仿真；影像为真实 Sentinel-2；图斑为算法候选，需人工复核。
- 不新增数据库表，不修改既有案件/工作台业务；只扩展 `app/sixg_api.py` 与 `/sixg` 页面。

### 编排模型

`_orchestration()` 把场景映射为四档：

| 场景 | 切片 | 回传瓦片 | 回传量 | 端到端 | 带宽节省 | 线索 |
| --- | --- | --- | --- | --- | --- | --- |
| 常态巡检 | eMBB | 4/4 | 6.4 MB | 约 323 ms | 0% | 2 个（P-01/P-02） |
| 卫星切换 | URLLC | 3/4 | 4.8 MB | 约 310 ms | 25% | 2 个 |
| 切片拥塞 | URLLC | 2/4 | 3.2 MB | 约 230 ms | 50% | 2 个 |
| 基站中断 | URLLC + NTN | 1/4 | 1.6 MB | 约 294 ms | 75% | 1 个（P-01，P-02 待补检） |

计算口径：单瓦片按 1.6 MB 估算；上行按平均下行带宽的 45% 折算；端到端 = 平均时延 + 回传时延 + ROI 推理耗时 + 6 ms 固定开销；SLA 1500 ms。瓦片为 2×2 网格，按候选图斑置信度排序；弱网只回传含候选的瓦片，未回传区域标记为“网络恢复后自动补检”，不伪装成全量覆盖。

### 代码与界面

- `app/sixg_api.py`：新增 `PROFILES`、`PROFILE_BY_SCENARIO`、`_full_detection()`、`_tile_of()`、`_detect(profile)`、`_orchestration()`；`/api/sixg/demo` 返回新增 `plan`（slice/tiles/uplink/compute/end_to_end/saved/steps/note），并按场景返回不同图斑；`/api/sixg/asset/{name}` 支持 `after_overlay_{profile}.png` 与 `diff_heatmap_{profile}.png`。
- `web/sixg.html`：双时相检测面板顶部新增 `.plan-bar`，展示网络切片、回传瓦片、端到端、有效线索、带宽节省；下方 `#plan-note` 说明弱网取舍。
- `web/sixg.js`：新增 `renderPlan()`，推演完成后同步更新；`web/sixg.css` 增加 `.plan-bar`、`.orch-note` 深浅样式。
- 报告新增“二、6G × AI 协同编排”表，并同步时间线“网络感知编排”节点。
