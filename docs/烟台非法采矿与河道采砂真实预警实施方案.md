# 烟台非法采矿与河道采砂真实预警实施方案

编制日期：2026-11-15，北京时间  
版本：V1.0，方案稿，尚未实施  
适用项目：`E:\警务遥感`  
主要依据：本项目烟台遥感进度、实验报告、方案选型、现有网站结构，以及本次核查的公开产品文档。

> 本次交付仅为实施方案。不修改网站，不重新处理影像，不提交 HyP3 任务，不采购数据，不改写已有进度记录。文档中的任务、接口、周期、指标和预算均是后续实施建议，不代表已经完成。

## 一、决策摘要

### 1.1 最终目标

在现有网站地图工具栏的“**中国地图**”右侧增加“**烟台专题**”入口。专题服务烟台市非法采矿及河道非法采砂的发现、研判、核查和复查，核心成果不是展示更多图层，而是形成能够持续运行的真实预警闭环：

1. 用有来源、有版本、有坐标精度说明的资料展示真实矿产资源分布。
2. 持续发现新增开挖、矿坑扩张、异常复采、河道扰动和岸边堆砂等可观测活动。
3. 按活动发生时有效的矿业权、采砂许可和工程审批核对合规性。
4. 输出有影像、有时间、有规则解释的疑似违法线索，并交给有权限的人员核查。
5. 通过现场与主管部门反馈，区分违法确认、合法活动、非采掘变化和证据不足。
6. 在积累足够可靠样本后，预测重点矿点、河段未来的异常活动风险，辅助安排巡查。

**推荐路线：权威资源与许可底图 + Sentinel-2 滚动变化监测 + Sentinel-1 辅助观测 + 有日期的高分影像重点复核 + 主管部门与现场核查。**

先做可解释规则与人工闭环，再判断是否值得训练专门模型。InSAR 不作为一期主线，也不作为判断地下非法开采的单一依据。

### 1.2 三条不可突破的边界

- **遥感能识别活动迹象，不能独立认定违法。** 同一裸地变化可能来自采矿、修路、农业、施工或修复。
- **公开卫星不能保证全市分钟级连续发现。** 本方案把“实时”落实为新观测到达后的自动处理与及时通知，同时明确每个区域的观测空窗。
- **缺数据不是没有问题。** 云遮挡、许可缺失、历史时点不清、目标太小或地下活动不可见时，必须显示“无法判断”或“资料待核”。

### 1.3 首期做什么、不做什么

| 范围 | 首期安排 |
|---|---|
| 烟台全市矿产资源底图 | 整理获准使用的正式资源资料，区分矿产地、矿业权、实际采掘范围；未取得资料的区域如实标缺 |
| 露天采矿 | 优先验证招远、莱州重点区；涵盖矿区外新扰动、已知矿区扩张、停闭矿区疑似复采 |
| 河道采砂 | 从界河、王河、大沽夹河候选范围中，由水利部门确定 1 至 2 段试点；通过后逐步扩展 |
| 地下采矿 | 以地表配套扰动、已登记停闭矿点和核查线索为主；形变只作独立辅助专题 |
| 烟台专题页面 | 复用现有三栏地图工作台，提供资源、监测、预警、核查联动 |
| 分钟级监控 | 仅在确有需求且获得授权的重点点位考虑视频或其他地面设备，不默认全市建设 |
| 海砂、海上执法 | 不纳入首期；原进度中的莱州湾、长岛海砂内容不自动扩入本任务 |
| 无关功能 | 不新增 3D 展示、大屏动画、6G 仿真、通用聊天机器人或与采矿采砂无关的自然灾害模块 |

### 1.4 本次采用的技能

- **主技能 `remote-sensing`**：限定不同传感器能看到什么；规范反射率、云掩膜、时序、变化检测和验证。
- **辅助技能 `gis-data`**：设计权威数据来源、坐标转换、几何质量、许可边界与数据版本管理。
- 对话采用简洁表达；方案文件保留完整实施细节。不因资料中出现其他专业术语而启动无关流程。

### 2.2 必须先纠正的产品语义问题

**既有记录将 LiCSAR 的 `sltd.geo.tif` 解释为累计 LOS 位移，不能沿用。**

本次读取 LiCSBAS 上游 `LiCSBAS03op_GACOS.py`，确认：

- 第 21 行将 `yyyymmdd.sltd.geo.tif` 列为 GACOS 输入。
- 第 35 行将 `sltd` 解释为 `Slantrange tropospheric delay in rad`，即斜距方向的对流层延迟，单位为弧度。
- 第 417 行附近读取该 TIFF 时明确注释 `Already in rad`。

因此，本项目把这组数值直接当作毫米位移、计算 2016 至 2021 年差值并据此判断“无局部沉降”的证据链不成立。**这些统计不得进入形变告警、模型标签或项目成效。** 本次只在新方案中标明问题，不修改原记录。

实施时应先确认实际下载文件的来源与产品类型，再使用合格干涉对、相干性和时序反演输出构建位移序列。需要统一参考点、参考历元、单位、符号及误差。历史目录停止更新也不等于整个地区此后没有可用 SAR 观测。

此外，即使获得可靠的“未检出沉降”结果，也不能推出“没有地下开采”。单轨 LOS 不能在没有水平运动假设的情况下直接当作垂直沉降。两对干涉的均值和高相干性也不足以排除大气、轨道、参考区及地形误差。[外部来源 E1、E2]

### 2.3 生产化前的其他修正清单

| 当前做法或风险 | 必须采取的措施 |
|---|---|
| 固定少量 11 月日期，虽然降低季节误报 | 保留同季历史对照，同时增加逐景滚动监测；不能一年只监测一个月 |
| Sentinel-2 脚本固定执行 `DN * 0.0001 - 0.1` | 根据每个产品的 processing baseline、scale、offset 和是否已 harmonize 转换；不得再次重复扣偏移 |
| 指数计算前裁切反射率到 0 至 1 | 分开保留物理计算数据和显示数据；登记负值、饱和与异常像元，评估裁切对暗水体的影响 |
| 陆地试验 `VALID_SCL = {4, 5, 7}` 排除了水体 | 河道通道必须保留有效水体像元，另行设计水体质量控制 |
| B11 为 20 m，重采样到 10 m | 报告原生分辨率；不得宣称得到真实 10 m 的短波红外细节 |
| S1 只按升轨及接近日期选景 | 进一步匹配相对轨道、极化、模式、入射角和有效足迹；跨卫星时核查可比性 |
| STAC 单页检索 | 正确处理分页、重处理版本与同次过境重复瓦片，避免漏景或重复告警 |
| 矢量化与面积筛选 | 测试仅输出变化前景，不将背景多边形或边缘缺测当成候选；统计图斑与有效观测面积 |
| 在线底图目视复核 | 未知拍摄日期的底图仅可按许可用于导航参考，不作为当前活动、历史标签或训练真值 |
| 任意缓冲区参与判断 | 搜索缓冲区不等于法定边界；越界判断要使用正式边界及测量误差 |
| 现有自然风险分值 | 不作为非法采矿概率，不复制到烟台预警分值 |

以上是后续质量门槛，不是本次已经完成的代码修复。

## 三、把“真实预警”定义为可验收的业务能力

### 3.1 分开保存四类判断

同一事件至少有四组独立字段，不能压成一个“违法概率”。

| 维度 | 建议值 | 含义 |
|---|---|---|
| 观测状态 | 有效、局部有效、遮挡、超期、目标低于能力范围 | 是否有足够观测支持判断 |
| 活动判断 | 疑似采矿、疑似采砂、非采掘变化、未检出、无法判断 | 遥感及其他材料能说明的活动类型 |
| 合规判断 | 疑似冲突、未发现已核验冲突、许可待核、主管部门确认违法、主管部门确认合规 | 许可和审批关系；“未发现冲突”不等于全面合法 |
| 处置状态 | 待研判、待补资料、待现场核查、已核查、持续复查、关闭 | 工作流进度 |

页面可以展示“疑似采砂，许可待核，建议核查”，不能在许可缺失时自动显示“非法采砂”。“确认违法”必须附有权限的业务人员录入的正式核验依据，不由模型生成。

### 3.2 一条有效线索必须具备的内容

1. 唯一事件编号、位置、图斑或河段，以及行政归属。
2. 异常类型与明确的触发规则。
3. 观测前后影像，或单次高分观测与其他独立材料。
4. 采集时间、产品编号、空间分辨率、有效像元比例和最近一次有效观测时间。
5. 最后一次未见异常与首次见到异常的时间区间；不知道起始时间时不得编造。
6. 对应矿业权或采砂许可的版本、有效期和匹配结果。
7. 云、阴影、水位、洪水、施工、修复等混淆因素。
8. 优先级及其原因、下一步核查任务、负责单位、处理期限。
9. 数据来源、处理版本、参数与原始文件校验值。

### 3.3 必须分别统计的效果

- 活动检出效果：是否确有开挖、堆砂等目标活动。
- 合规筛查效果：是否确有许可范围、期限或其他经核验的冲突。
- 违法确认效果：有权限的部门最终确认的违法线索比例。
- 覆盖效果：哪些矿区、河段近期有有效观测，哪些处于监测空窗。
- 处置效果：从线索形成到研判、核查、反馈分别用了多久。

不得将“发现裸地变化准确率”“疑似开采准确率”或“人工点击确认率”写成“违法识别准确率”。

## 四、空间范围与试点选择

### 4.1 全市底图，重点试点，分批推广

**底图范围**采用授权的现行烟台市及区县行政边界。全市先完成数据目录和缺口标识，数据齐备区域再逐批上线监测。地图覆盖全市不意味着全市已经获得同等监测能力。

**采矿试点**优先选择招远、莱州具有可核实矿权与历史活动资料的露天扰动区。黄金、石材、煤炭等仅作为依据现有进度提出的调查分类；具体矿种、数量、位置、规模须由正式资源台账确认。不得按行政区名自动生成矿产点。

**河道试点**从界河、王河、大沽夹河中选取 1 至 2 条河流的代表性河段，合计建议 20 至 40 km。由水利部门确认名称、河段起止、管理范围、禁采要求和合法工程。宽度不足以支持卫星判读的河段，要在选址时识别出来。

**地下开采补充**在龙口等有明确业务需求的区域单独论证。不以地下模型是否完成阻塞露天和河道试点。

### 4.2 首批样区建议

- 采矿：约 30 至 50 个已登记矿点、停闭矿点及邻近对照区，兼有合法活动、历史遗留和非采矿扰动。
- 河道：约 20 至 30 个分段单元，覆盖不同河宽、水位变化、城郊施工和自然沙洲类型。
- 困难样本：优先纳入现有 A、B、D 区，但必须补充同日期或可验证时段的参考材料。
- 未知区域：每月从已知矿点之外随机抽查部分网格，避免系统只会发现“原来就知道的矿”。

这些数量是工作量建议，不是现有真实矿点数量。试点选择不公开个人身份、企业经营敏感信息或非授权精确坐标。

## 五、真实矿产资源与合规数据底座

### 5.1 先取得什么数据

| 数据层 | 首选来源与责任方 | 必需字段或资料 | 更新与验收建议 |
|---|---|---|---|
| 矿产地与已查明资源分布 | 自然资源主管部门、地质资料主管机构的授权数据 | 矿产地编号、矿种、点/面几何、调查年代、勘查程度、空间精度、公开级别 | 初始完整入库；至少季度核对版本；不能用矿企地址代替矿产位置 |
| 采矿权 | 有权登记部门的现行及历史台账 | 证号、范围拐点、有效期、状态、开采矿种/方式、登记版本；涉及深度需保留高程范围 | 建议每日检查变更通知，每周对账；紧急变更及时生效 |
| 探矿权 | 有权登记部门 | 独立权利类型、范围、期限、勘查项目资料 | 与采矿权分层；探矿权不等于生产性采矿许可 |
| 实际采掘与停闭矿点 | 自然资源及属地合法共享资料、经核查遥感图斑 | 现场范围、活动状态、关闭/停产依据、核查日期 | 每次核查更新；保留历史，不覆盖旧结论 |
| 河道管理范围 | 水利部门、河湖管理机构 | 河道名称、管理范围线、分段编号、堤防及敏感设施 | 正式划界版本变更时更新；河流中心线不能替代管理范围 |
| 采砂许可与禁采要求 | 有权水行政主管部门 | 许可号、有效期、允许区域、开采时段、深度/总量条件、禁采区/期及发布依据 | 禁采通知当日更新；许可定期对账；规则保留生效与失效时间 |
| 疏浚、清淤、治理工程 | 水利及相关审批部门 | 批复、工程边界、工期、施工内容、允许外运或处置要求 | 工程开始前登记，变更和完工及时更新 |
| 用地、林地、修复等审批 | 相关主管部门的授权资料 | 项目范围、审批类型、有效期、用途、业务联系人 | 按发布节奏同步；不能用单一采矿证判断所有合规问题 |
| 生态保护等约束 | 相关主管部门 | 正式边界、法律属性、版本、使用权限 | 按正式版本更新；公开粗略图不得直接用于执法级越界判断 |
| 历史核查与行政处理 | 有权限的业务部门 | 事件发生时段、活动类型、处理结论、依据、证据质量 | 审核后入库；脱敏；区分举报、怀疑、立案与最终认定 |
| 水位、降雨、洪水与调度 | 授权水文、水利资料；公开资料作补充 | 站点、采样时间、单位、质量码、洪水/泄水事件 | 与影像时间对齐；缺测明确标识，不能用预报冒充实测 |

“每周对账”等是拟定运行目标，需和提供方约定。若对方只能按月提供，系统必须展示实际更新时间，不能模拟每日更新。

### 5.2 公开资料与正式资料的分工

1. 公开矿产资源规划、公告和地质资料用于确认数据目录与区域背景。
2. 正式矿业权范围与时态许可用于形成可追溯的合规线索。
3. 批准文件与主管部门核验用于处理续期、历史状态、调整及公开台账不完整问题。
4. 有日期的遥感图斑用于表达地表实际活动，不反向伪造地质资源分布。

本次核查了烟台市政府、水利局、自然资源部的门户入口；**未取得可直接用于生产的烟台全量矿产地、矿权或采砂许可矢量数据**。自然资源和规划部门站点、全国地质资料馆入口本次存在连接问题，具体数据服务与获取条件仍需确认。不能把门户可访问写成数据已经可用。

截至方案日期，不能直接把规划期为 2021 至 2025 年的文件当作 2026 年现行管理依据。应核实现行规划、延续安排、调整文件及当期有效许可。

### 5.3 入库规范

统一数据登记表至少包括：

```text
dataset_id, layer_type, authority, source_title, source_url_or_document_id
release_date, obtained_at, valid_from, valid_to, ingested_at, version
original_crs, working_crs, transform_method, spatial_accuracy_m
license_or_authorization, access_level, completeness_scope
file_sha256, reviewer, review_status
```

- 原始文件只读保存，转换产物另存。保存转换前后要素数、范围、空几何、重复和无效几何统计。
- 保留资料生效时间与系统收到时间，两者分开。新收到的续期文件可能改变旧事件的判断。
- WGS84 GeoJSON 使用经度、纬度顺序。网页可用 Web Mercator 显示，但面积和距离不在经纬度或 Web Mercator 中直接计算。
- 正式边界优先保留原始 CGCS2000 等坐标及其投影定义。分析采用适合范围的米制投影或椭球面积；现有 EPSG:32651 适用性需逐区检查，尤其是跨 120°E 的范围。
- 使用国产底图时确认其坐标约定，不能把 WGS84、GCJ-02 等混用后直接判断越界。
- 扫描图只有在使用许可允许、具有控制点且配准误差可量化时才可数字化；只能作为相应精度的参考层，不能包装成正式拐点边界。
- 资源储量、地下矿体模型等可能有保密或使用限制。只入库获准字段，不要求为了页面展示公开敏感资料。

### 5.4 真实分布的显示规则

- 矿产地用矿种符号表示，显示来源、资料年份与精度；资源点不是正在开采的矿山。
- 采矿权、探矿权、已知实际采掘范围分别成层，使用不同线型。
- 已知点位只有点坐标时只画点，不扩画虚构矿体面。
- 正式资源分布不因模型推断而改变。模型发现未知疑似采掘点时，进入“待核活动”层。
- 地图显示资料覆盖区与缺失区。缺失区不显示“资源为零”或“违法为零”。

### 5.5 数据拿不到时的降级

| 缺口 | 可以做 | 不可以做 |
|---|---|---|
| 没有完整矿权范围 | 发现疑似采掘活动，申请属地逐点核验 | 根据公开名单查无此项就认定无证 |
| 没有采砂许可与工程台账 | 河道扰动监测，形成待核清单 | 把清淤、疏浚、治理施工自动当非法采砂 |
| 只有粗略资源图 | 标注区域性分布及精度限制 | 生成精确矿体边界、储量或可采规模 |
| 没有高分或现场材料 | 保留中低置信度候选，延长观察 | 对小设备、洞口、窄河道作确定识别 |
| 没有持续核查能力 | 内部试验或影子运行 | 宣称已经实现业务级真实违法预警 |

## 六、观测体系与时效承诺

### 6.1 传感器分工

| 数据 | 核心用途 | 明确限制 | 使用策略 |
|---|---|---|---|
| Sentinel-2 L2A | 裸地扩张、植被损失、矿坑/堆场变化、水体及沙洲变化 | 可见光与近红外主要为 10 m，SWIR 为 20 m；云、阴影和小目标限制明显 | 全市筛查主通道；每景质量合格后处理 |
| Sentinel-1 GRD/RTC | 云多时补充结构和散射变化，辅助水陆变化 | 10 m 网格间距不等于 10 m 有效分辨率；湿度、耕作和视角产生混淆 | 按同轨时序分析；不能独立认定采掘或违法 |
| Landsat L2 | 长时间背景、较大尺度变化补充 | 30 m，窄河道与小矿坑能力不足 | 作为历史背景，不与 S2 指数不加校准直接混比 |
| 获授权的高分/商业影像 | 重点候选的作业面、堆砂、道路和设备上下文复核 | 成像机会、费用、云和授权范围约束；“亚米级”不保证识别被遮挡洞口 | 按线索与固定重点区采购；明确成像日期和验收条件 |
| 无人机或现场照片 | 核实正在发生的作业与地物类型，补足小目标 | 需要授权、安全与空域条件；不能任意飞行 | 已派发核查任务后按权限使用 |
| 授权固定视频 | 少数高风险点位分钟级活动提示 | 仅覆盖视场；夜间、遮挡、断网影响明显；设备活动不等于违法 | 第二阶段按收益部署；不作为全市覆盖承诺 |
| InSAR | 指定地下开采相关形变线索、风险辅助 | 相干性、几何、参考点和多种非采矿形变影响；并非直接探测地下开采 | 样区论证通过后独立建设，不占用一期主线资源 |

Sentinel-2 官方说明的双星典型重访约为 5 天，中纬度几何覆盖可能更密；实际有效观测间隔必须依据烟台样区可用产品统计。星座运行、采集安排和云量会变化，不能把标称重访写成固定告警周期。[E3]

### 6.2 最小目标能力

首期不写“任何非法行为都能发现”。按目标和传感器定义服务边界：

- 露天变化筛查初始关注宽度约 30 至 50 m、面积约 0.3 至 0.5 ha 及以上的持续地表扰动；这是试验起点，需以验证结果确定，不能保证全部检出。
- 涉及 B11 等 20 m 波段的规则，识别稳定性按实际有效尺度评估，不以输出栅格的 10 m 标签替代。
- 小于上述尺度的明确高分线索可直接进入人工研判，不必等 Sentinel-2 达到面积阈值。
- 狭窄河道、小船、短时装运、隐蔽洞口、地下作业不能承诺由公开卫星可靠识别。
- 采砂量、采深和矿石产量不能从单张光学影像直接推算；需要测量、水文、地形差分或依法取得的其他材料。

### 6.3 时间拆解

每次事件分别记录：

```text
t_last_clear_before：最近一次有效且未见该变化的观测
t_observed：首次有效见到变化的观测
t_provider_available：提供方可访问时间，未知时明确为空
t_discovered：本系统发现产品的时间
t_processed：分析完成时间
t_alerted：线索通知时间
t_reviewed：人工研判时间
t_verified：现场或主管部门反馈时间
```

变化通常只能限定在两次有效观测之间。未观测到行为发生的瞬间，就不能把卫星过境时间写成开采开始时间。

**建议试点服务目标，均待压测与业务确认：**

- 影像目录每 6 小时检查一次；首次接入只建立基线，历史影像不当新预警。
- 对试点 AOI，在系统发现可用影像后，95% 在 6 小时内完成质量检查与候选分析。
- 线索达到发送条件后，95% 在 15 分钟内通过已授权渠道通知；发送失败重试并记录。
- 业务高优先级线索建议在 4 个工作小时内接收，1 个工作日内完成初审；现场时限由属地能力和安全条件确定。
- 重点区域超过 14 天没有有效观测，提示“观测缺口”；该阈值用于启动补充观测，不代表 14 天内一定能发现行为。

以上时间均不包含无法控制的过境等待、云遮挡和上游产品发布延迟。总发现延迟必须单独报告，不能只报计算耗时。

若业务必须掌握正在进行、持续数小时的盗采，卫星方案本身不满足要求。应选定少量重点出入口或河段，另行配置获得授权的地面观测与快速核查机制。

## 七、两条独立的检测流程

### 7.1 公共预处理

1. **建立产品清单。** 保存 STAC Item、产品版本、采集日期、足迹、原始元数据与资产校验信息。正确处理分页和去重。
2. **检查原始质量。** 核实波段、单位、NoData、实际空间分辨率、CRS 和有效范围。
3. **转换反射率。** 用产品元数据应用比例和偏移；对 harmonized 数据避免重复校正。掩膜先保留 NoData。
4. **剔除坏观测。** 逐像元处理云、云影、雪和饱和。场景总云量仅作初筛，必须计算目标图斑及周边的有效覆盖。
5. **统一网格。** 连续值合理重采样，SCL 等类别值用最近邻；核验不同日期配准偏差。
6. **保留不确定性。** 云边缘、阴影、配准不良区域不能生成精确边界结论。
7. **输出可复现记录。** 输入文件、参数、软件环境、代码版本与产物路径共同保存。

默认以候选及其上下文 80% 以上像元有效作为初始自动研判条件，并对最关键的变化边缘单独检查；阈值须在样区验证。达不到条件进入低质量队列，不产生“未发现活动”的结论。

### 7.2 露天采矿通道

**步骤 A：建立两类基线。**

- 短期基线：最近 30 至 90 天的有效观测，保留逐景数据；用于识别突然或持续扩张。
- 季节基线：尽可能采用过去 2 至 3 年相近日序窗口及物候状态，解释果园、收获和季节性裸土。
- 新区域资料不足时先建基线；历史影像用于背景，不发“刚发生”的通知。

**步骤 B：产生变化候选。**

组合 NDVI、BSI、原始反射率、裸地占比、对象形状、边缘推进、道路与堆场变化。阈值从当地稳定区与已核实样区分布中标定，不直接把旧试验的单一阈值扩到全市。

**步骤 C：按活动对象判读。**

区分矿坑扩张、剥离面、新道路、弃渣/堆料、停闭矿区新增活动。与农田、果园、梯田、光伏、温室、养殖、普通建设及土地整治分开。使用背景土地覆盖信息辅助，但不能因“历史上是耕地”就排除后续真实开挖。

**步骤 D：验证持续性与独立证据。**

常规候选需要第二次有效观测，或有日期高分/现场材料支持；同一景影像计算多个指数不算多份独立证据。明显且具有可靠高分材料的高影响事件可立即进入人工核查，不机械等待下一次卫星。

第二次观测仅确认图斑仍然存在时，只能提高“变化真实存在”的可信度，不能证明仍在开采。判断持续活动需要新的外扩、物料/道路变化、作业设备的时序证据或现场信息。对长期不变的历史矿坑不得重复生成“正在开采”告警。

**步骤 E：进行合规匹配。**

分别检查采矿权、停闭状态、项目工期、用地和修复审批。矿权内也可能存在其他不符合条件的活动，矿权外的裸地也可能是合法道路或其他工程，因此匹配只能给出待核问题与依据。

**步骤 F：形成事件而非重复图斑。**

同一位置的连续扩张归入同一事件，保留每次边界和面积。只有新的外扩、停闭后的复发、强度显著增加或合规状态变化才升级，不因每次过境重新报一遍。

### 7.3 河道采砂通道

不能把露天采矿的陆地掩膜与阈值直接搬到河流。

1. **建立法定与自然双底图。** 使用正式管理范围、许可区、禁采区与工程范围；另维护动态水面、沙洲、滩地、岸坡和交通出入口。
2. **匹配水文条件。** 优先比较接近水位、流量和季节的影像。记录降雨、洪水、泄水与上游工程；无实测资料时降低置信度。
3. **保留有效水体。** 结合 NDWI/MNDWI 等辅助提取水陆变化，正确处理暗水、浑水、阴影和窄河混合像元。
4. **寻找组合迹象。** 包括非自然沙洲切割、持续坑槽、岸边新堆砂、临时装运道路、反复作业面变化，以及高分影像上的设备与作业关系。
5. **排除主要替代解释。** 洪水冲淤、自然河道摆动、季节退水露滩、桥梁施工、合法清淤、河道治理和岸坡修复。
6. **核对许可与时段。** 检查许可范围、有效期、禁采期及工程批复。涉及深度和总量限制时转人工或专业测量，不由二维影像直接判定。
7. **派发河段核查。** 提供疑似作业区、可达位置、最近观测时间、许可疑点与所需补充材料，而不是仅给出一条浑浊水体曲线。

水体浑浊只是辅助特征，不能独立触发“非法采砂”。普通 10 m 光学影像也不能可靠完成小型采砂船或车牌识别。

### 7.4 地下活动与 InSAR 的位置

一期只保留“疑似地下活动相关线索”类别，不宣称直接探测地下采掘。

后续确需增加 InSAR 时，先在有地面参考资料的样区验证：同轨 SLC、时空基线、相干性、解缠、轨道与 DEM 误差、大气校正、参考区、时序网络连通性及不确定度。使用 SBAS/PS 等成熟方法及已有软件，避免自写核心反演算法。

沉降还可能来自地下水、自然压实、工程或其他原因。只有与采掘资料、空间位置、时间和现场情况一致时，才能作为辅助线索。无可靠相干目标的区域显示“形变不可判”，不显示零形变。

## 八、合规匹配与预警规则

### 8.1 边界与时间必须同时匹配

边界误差包括许可图精度、影像定位误差、配准误差和图斑分割误差。由样点与数据规格估计合成误差带，采用保守方法并记录依据。固定的 50 m 或 200 m 搜索缓冲不能成为越界认定标准。

- 候选仅落在边界不确定带：显示“边界待核”，申请更精确资料或测量。
- 候选明显超出不确定带：形成“疑似超出登记范围”线索，仍核查其活动性质和其他审批。
- 许可只覆盖部分图斑：分别记录相交面积、未匹配部分及误差，不以质心是否在内决定整片合法性。
- 异常发生区间跨越许可变更：按区间内可能版本评估，不能只用今天的台账定性过去事件。
- 公开台账未匹配：先判断台账覆盖是否完整，查询续期或变更；不自动标“无证”。

### 8.2 规则矩阵

| 编号 | 触发证据 | 结果表述 | 优先处理 |
|---|---|---|---|
| M1 | 有效影像出现新裸化，但没有可靠作业形态或独立证据 | 地表扰动候选 | 对照物候、工程及历史影像 |
| M2 | 新增或扩张的采掘活动有独立证据支持，且在精度允许条件下明显超出登记范围 | 疑似范围冲突，需核查 | 核对正式拐点和现场用途 |
| M3 | 经核实停闭状态的矿点出现新的持续作业迹象 | 疑似复采 | 核查停闭/复工文件与当前活动 |
| M4 | 已核实采掘活动，但许可库覆盖不完整或资料超期 | 许可待核 | 数据补齐，不直接发违法结论 |
| S1 | 河滩变化与洪水/退水一致，缺少作业证据 | 自然或水文变化待确认 | 水文对照，必要时跟踪 |
| S2 | 同期堆砂、作业面、运输联系等多项支持，且有有效禁采依据 | 疑似禁采期/区作业 | 水利部门优先核查 |
| S3 | 存在有效疏浚批复，但活动超出项目边界或时段 | 疑似工程范围/时段冲突 | 调取项目变更和施工资料 |
| Q1 | 云遮挡、资料过期、配准不合格或目标太小 | 无法判断/观测缺口 | 补充观测，不计为正常 |
| V1 | 有权限人员提交正式核验依据与结论 | 确认违法/确认合规/非采掘活动 | 留存依据，转处置或关闭 |

### 8.3 优先级而非伪概率

首期采用可解释等级：

- **P1，优先核查**：强活动证据，且存在可靠的许可冲突或经核实停闭后的复发；由人工确认发送。
- **P2，常规核查**：活动较可信，但需补充许可、时点或范围依据。
- **P3，观察候选**：只有单次或较弱变化，安排继续观测。
- **Q，资料不足**：不能形成有效活动判断；单列数据补齐队列。

面积、距离居民区或敏感设施、复发情况可以影响处理顺序，但不改变证据等级。首期不展示“违法概率 93%”等未校准数字。

高优先级并不意味着已经违法。提醒对象是有权限的业务人员，不自动向社会发布企业违法名单，也不自动触发处罚。

### 8.4 去重、升级和撤回

同一地点、同一活动类型、连续时段的候选合并管理；空间重叠与时间窗口通过样区标定。每次更新保留旧版本。

新的有效证据或范围扩大可以升级。续期文件、工程批复或现场解释可以降级、撤回。撤回须说明原因并通知原接收人，历史记录不能被静默删除。

## 九、预测能力的实施顺序

### 9.1 先识别，再预测

用户提出的“有无非法行为预测”分成两件事：

1. **当前/近期是否存在疑似行为**：通过实际观测及合规资料研判，是首期必须交付的能力。
2. **未来哪些地点更需要巡查**：预测未来 7 天或 30 天内的异常活动风险，待标签与长期样本充分后建设。

不能用第二类风险排名替代第一类实际发现，也不能把没有观测的未来事件描绘成已发生。

### 9.2 模型选择

首期使用规则和人工复核。若评估显示主要问题是复杂地物混淆，下一步先比较对象级随机森林等成熟基线，输入地物、时序、形状及水文特征。

只有在拥有足够合法使用且与日期匹配的高分标注后，才考虑变化分割或作业目标检测模型。不得直接以网上预训练模型的输出作为违法证据。

预测模型的对象限定为矿点、河段或网格，不对个人的犯罪倾向评分。矿产分布只表示资源背景，不是违法标签。

### 9.3 预测上线门槛

- 标签区分确有活动、最终违法认定、合法作业、非采掘变化和资料不足；投诉和传闻不是违法真值。
- 历史特征按当时能获得的数据构建，不能使用事后核查结果、后补许可或未来影像泄漏答案。
- 按空间块、矿点/河段及时间分割训练和测试，相邻像元及同一事件不得分到两边。
- 与“按最近一次异常排序”“按复发次数排序”等简单基线比较。
- 评估 PR-AUC、固定巡查量下的命中率、召回、校准和置信区间；不以总体准确率作为唯一指标。
- 样本不足、跨季节失效或没有优于基线时，不上线概率模型，保留可解释巡查优先级。

预测输出即使经过校准，也只能是明确时窗与适用区域内的“异常活动风险”。没有足够且可靠的违法认定样本时，不使用“未来违法概率”名称。

## 十、网站“烟台专题”方案

### 10.1 入口与范围

截图及源码中的地图工具栏包含“2D / 3D / 研究区 / 中国地图”。入口应放在“**中国地图**”之后，而不是放在页面最右侧详情栏。

```text
[2D] [3D]  研究区  中国地图  烟台专题
```

建议以 `/yantai` 作为专题路由，复用现有登录、基础样式、地图与核查工作流。该路由是拟定设计，当前尚未实现。

专题初始显示烟台全域，支持按区县、矿种、河流、时间和处理状态筛选。保留返回原研究区的入口。主站仅增加入口，不改动现有两研究区的业务逻辑。

### 10.2 三栏布局

**左栏：监测与任务。** 显示待核 P1/P2、待补资料、近 7/30 天新增事件、核查完成情况；矿区与河道分标签页。数量来自真实数据库。空库显示“尚无已入库数据”，不用演示数字填充。

**中栏：烟台地图。** 默认展示行政边界、真实资源点/面、河流及待核事件。矿业权、探矿权、许可、工程、时序变化和观测缺口按需勾选。资源类别与预警等级分别编码，不用同一颜色同时表示两种含义。

**右栏：事件研判。** 选中事件后展示前后对比、逐景时间线、活动证据、许可匹配、混淆解释、核查结果与建议任务。重要字段缺失直接写“未取得”，不以 0 代替。

### 10.3 每个对象的详情

| 对象 | 必须显示 |
|---|---|
| 矿产资源点/面 | 名称或编号、矿种、来源、资料年代、空间精度、公开级别、关联矿业权；不默认公开储量 |
| 矿业权 | 权利类型、状态、有效期、授权可见的登记范围与版本；关联活动不能自动继承“合法”标签 |
| 河段 | 正式名称、管理范围、许可与禁采时段、工程状态、最新有效影像、水文条件 |
| 预警事件 | 活动类型、合规状态、优先级、前后影像、发生时间区间、变化面积及不确定性、规则与待核事项 |
| 观测缺口 | 缺口原因、最近有效日期、受影响范围、下一步补观测安排 |

### 10.4 交互与安全要求

- 使用现有图层选择、定位、时间筛选和详情面板模式，不新造一套框架。
- 前后影像采用同步视野对比，明确每幅采集日期、传感器和比例尺，不能把底图日期当影像日期。
- 在概览持续显示最近成功检查时间、最近有效影像日期与数据覆盖率；不因时钟跳动就显示“实时在线监测正常”。
- 不显示未经校准的违法概率，不把旧项目的自然灾害风险仪表复制进来。
- 允许研判人员选择“需补许可”“需高分复核”“需现场核查”“非采掘变化”等操作，并填写依据。
- 手机端保留地图、队列和详情切换；不要求照搬桌面三栏，避免遮挡与文字溢出。
- 精确矿权、内部许可、现场图片及人员信息按角色授权。公网版如需开放，使用另行批准的概化数据。
- 保留底图与遥感来源署名，核对地图服务、缓存、分析和衍生产物的使用条款。

### 10.5 三个验收场景

1. 点击“中国地图”右边的“烟台专题”，进入烟台范围；旧研究区仍可正常返回。
2. 点击真实矿产点，可看到正式来源与矿种，再切换关联矿权和近期活动；资料缺失有明确标记。
3. 点击一条疑似采砂线索，可看到前后影像、禁采/许可依据、水位干扰和派发任务；没有证据时不能点击生成“已违法”结论。

## 十一、最小技术架构与数据契约

### 11.1 复用现有系统

现有项目采用原生 HTML/CSS/JavaScript、Leaflet、FastAPI 与 SQLite。首期沿用这些技术，不为单一专题引入新前端框架或分布式平台。

现有 `app/imagery_watch.py` 主要负责新影像发现，不能等同异常识别。拟在其后增加独立处理任务：产品发现、质量检查、采矿/河道分析、合规关联、人工研判、事件通知。

试点可采用一个独立 Python worker、持久化任务表和单一受控调度入口。不要在多个 Web worker 中重复启动计划任务。栅格用 COG，权威矢量用 GeoPackage 或受控数据库，业务状态继续复用 SQLite；并发写入与规模确实达到瓶颈后再评估 PostGIS。

### 11.2 拟新增或适配的数据对象

| 对象 | 关键字段 | 原则 |
|---|---|---|
| 数据版本 | `dataset_id, version, valid_from, valid_to, authority, sha256` | 所有空间与合规判断关联具体版本 |
| 资源与权利 | `resource_id/right_id, type, geometry_ref, status, validity, source_id` | 资源、探矿权、采矿权分型，不混为一张资源点表 |
| 河段与许可 | `reach_id, permit_id, permit_type, geometry_ref, validity, conditions` | 包括采砂与治理工程，不遗漏例外审批 |
| 观测 | `observation_id, product_id, acquired_at, discovered_at, quality, footprint` | 保存有效性及未通过原因 |
| 变化候选 | `candidate_id, type, geometry, before_id, after_id, features, rule_version` | 可复算，可追踪到输入 |
| 事件 | `event_id, domain, activity_status, compliance_status, priority, lifecycle` | 活动、合规和工作流状态分开 |
| 核查与依据 | `event_id, case_id, reviewer, decision, basis, verified_at` | 关联已有案件/任务，不重复建设移动核查 |
| 运行任务 | `job_id, input_key, stage, status, attempt, started_at, finished_at, error` | 重试、断点恢复与幂等 |

空间数据不一定全部存入 SQLite。表内可保存受控对象引用，避免大栅格进入业务数据库。

### 11.3 拟定接口

以下为未来接口契约建议，不是当前已存在接口：

```text
GET  /api/yantai/catalog                 图层来源、版本与可见权限
GET  /api/yantai/resources               按范围/矿种查询资源
GET  /api/yantai/reaches                 河段与授权可见的许可摘要
GET  /api/yantai/coverage                观测时间、缺口与质量
GET  /api/yantai/events                  事件筛选与分页
GET  /api/yantai/events/{id}             证据、合规匹配和历史
POST /api/yantai/events/{id}/reviews     有权限人员的研判记录
POST /api/yantai/events/{id}/dispatch    关联已有工作台任务
```

列表接口支持范围裁剪、分页与时间条件。接口返回中包含 `as_of`、`data_status`、`source_version`，便于前端区分真实、缺失与过期数据。原始敏感文件通过鉴权接口按需提供，不放入公开静态目录。

### 11.4 状态与容错

处理任务按以下顺序运行：

```text
discovered
queued
processing
quality_rejected / processed
awaiting_review
published / dismissed / needs_data
```

同一产品、AOI、算法版本生成唯一处理键；重复调度不重复创建事件。任务失败保存错误类别并有限重试，无法恢复时进入人工检查。上游访问失败只能显示“更新失败”，不能显示“没有新异常”。

历史重算与在线告警分开。新算法回放旧影像时更新历史分析版本，不批量向值班人员发送旧事件。告警发送和事件保存使用可恢复的发送记录，避免网络重试导致重复通知。

### 11.5 与现有核查状态衔接

现有 `confirmed / excluded / inconclusive` 不应直接映射为“违法 / 合法 / 未知”。必须加上确认对象与依据：

- `confirmed` 可以是“确认存在采掘活动”，不必然是“确认违法”。
- `excluded` 可以是“排除该条疑似线索”，不代表该区域永远没有违法。
- `inconclusive` 保留资料不足原因，不作为负样本。

已有文件哈希与审计链可继续使用，但它们证明登记后文件一致性，不证明影像内容解释正确、许可完备或法律结论成立。

### 11.6 安全与运维

- 授权分为查看公开资源、内部研判、外业核查、业务确认、系统管理等角色。
- 原始凭据留在服务器安全配置中，不进入网页、截图、日志或方案附件。
- 精确坐标、许可附件与外业资料不上传未经批准的第三方服务。
- 数据导出记录操作者、范围、用途与时间；原始材料和派生结论都可追溯。
- 业务状态每日备份；资料按重要性保留异地副本并定期演练恢复。
- 监控目录检查失败、任务积压、影像过期、质量拒绝率、重复事件、通知失败和核查超期。
- 浏览器回归只验证后续实施成果。本次不启动服务器、不打开或操作生产页面。

## 十二、研判、核查与解决方案闭环

### 12.1 工作流

1. 遥感通道生成候选并说明证据质量。
2. 研判员核查时序、地物类型和主要混淆因素。
3. 合规人员核对许可、项目审批及事件时点。
4. 明确是否需要补资料、高分复核或现场任务。
5. 属地按权限核查活动性质、时段、位置和关联主体。
6. 有权限人员录入结论与依据，必要时走既有业务处理程序。
7. 系统继续监测，判断是否停止、整改、复发或持续无法观测。
8. 合格反馈进入训练与评估样本，不合格反馈留在待确认队列。

### 12.2 各方职责

| 角色 | 主要责任 |
|---|---|
| 项目负责人 | 确认范围、数据授权、试点资源与验收标准 |
| 遥感/GIS 人员 | 质量控制、变化解释、能力边界和样本评估 |
| 自然资源业务联系人 | 矿产资料、矿业权、停闭及相关审批核验 |
| 水利业务联系人 | 河道范围、采砂许可、禁采要求和工程核验 |
| 属地核查人员 | 现场事实核实与规范反馈；按权限开展后续处置 |
| 系统开发/运维 | 数据管道、页面、权限、可靠性与审计 |

实际部门职责按当地现行机制落实。本方案不替代行政权限划分。

### 12.3 线索对应的解决路径

| 主要问题 | 优先行动 | 关闭或进入复查的条件 |
|---|---|---|
| 疑似新增矿坑，许可缺失 | 先查登记与项目审批，再决定现场核查 | 有明确活动解释或形成经审核的后续任务 |
| 疑似越界 | 取得正式边界，检查定位误差，必要时现场测量 | 范围关系有足够精度的核验依据 |
| 停闭矿点疑似复采 | 核对复工文件、近期高分或现场活动 | 状态澄清；持续监测后续活动 |
| 禁采期河道出现作业 | 核验是否为依法批准的工程及活动性质 | 水利业务确认并记录依据 |
| 洪水后出现河滩变化 | 对照洪水、水位及上下游变化 | 有充分自然解释则排除；不足则继续观察 |
| 小目标或持续云遮挡 | 定向申请高分或安排授权外业 | 获得有效观测，或明确超出服务能力 |
| 同一点位反复发生 | 加密观测，复盘历次核查，评估固定设备是否有实际收益 | 形成可执行的巡查/复查安排，而非单纯提高分数 |

系统输出的是供有权限人员执行的建议，不自动给出处罚决定。紧急现场处置还需遵守安全、天气、河道和作业区管理要求。

## 十三、实施工作包与里程碑

### 13.1 启动条件

以下条件满足后才计算正式试点工期：

- 明确自然资源、水利及属地核查联系人。
- 至少一个采矿样区和一个河道样区取得足够的许可与参考资料。
- 确认高分或现场复核的可用渠道与容量。
- 约定内部展示范围、数据保存位置及反馈权限。

资料尚未到位时可以做目录整理和技术准备，但不能将等待时间掩盖成开发完成。

### 13.2 建议 12 周受控试点

| 阶段 | 时间 | 关键任务 | 交付物 | 通过条件 |
|---|---|---|---|---|
| G0 资料与口径 | 第 1 至 2 周 | 获得样区边界、矿权/采砂及工程资料；审核 LiCSAR 等旧结论 | 数据目录、授权清单、缺口表、样区与规则口径 | 来源可追溯；不把缺失许可当无证；旧错误不进入模型 |
| G1 可信底图 | 第 3 至 4 周 | 资源、矿业权、河段和许可分层入库；坐标与时态校验 | 版本化样区底图、质量报告、数据字典 | 正式层几何与原始依据抽检一致；误差范围明确 |
| G2 监测原型 | 第 5 至 6 周 | 两条检测通道、季节基线、水文对照、候选去重 | 可复算候选、样本集、初步混淆分析 | 能解释真实变化与典型误报；输出缺测状态 |
| G3 专题与闭环 | 第 7 至 8 周 | 工具栏入口、专题图层、事件详情、鉴权与核查衔接 | 可用专题、通知与反馈流程、回归结果 | 每条事件可追溯；旧页面不回归；权限隔离通过 |
| G4 影子运行 | 第 9 至 12 周 | 连续自动运行、人工审核全部高优先级、抽样非告警区域 | 时效报告、误报漏报报告、核查负荷、问题清单 | 不自动对外认定违法；指标达到试点约定或明确未达原因 |

第 12 周产出的是“是否具备有限范围业务运行条件”的结论，不保证完成全市推广。若有效影像或正样本不足，应延长观察，而不是用模拟案例凑验收。

首轮通过后，再至少安排 8 至 12 周扩大范围的前瞻运行。跨季节泛化需要历史回放与后续不同季节真实观察共同验证；一个月影子运行不能证明全年能力。

### 13.3 各工作包可复查的完成标准

- **数据包**：每个正式图层有来源、授权、时效、坐标、精度和缺口；抽检坐标与许可一致。
- **处理包**：输入固定时可复算；掩膜、配准、单位和时序检查通过；失败不会变成“无异常”。
- **规则包**：每条规则有支持证据、适用对象、排除条件和版本；真实误报可解释。
- **页面包**：入口位置正确；真实资源与模型候选不混淆；小屏无内容遮挡；旧页面正常。
- **业务包**：至少完成若干真实候选从发现到反馈的全流程；“排除”和“资料不足”也允许正常闭环。
- **验收包**：提供留出集、抽样方案、时效分布、置信区间与未覆盖区域，不只提供成功截图。

## 十四、验证设计与上线标准

### 14.1 样本建设

1. 收集过去约 24 个月可核实的活动及非活动案例；更早资料可作为背景。
2. 每个样本关联独立矿点/河段、发生时段、有日期参考影像或现场材料、活动与合规两类标签。
3. 困难负样本包含果园、梯田、收获、光伏、修路、养殖、修复、合法疏浚、洪水冲淤及退水。
4. 由至少两名具备相应能力的人员复核有争议样本；争议未解不强制归为正或负。
5. 训练、调参和验收样本按事件、空间块与时间隔离。留出集冻结后不得反复用它调阈值。

初始建议每条通道争取不少于 30 个独立、已核实的目标活动事件和 100 个具有代表性的非目标事件。此数量只支持初步诊断，不保证统计精度；无法获得足够样本时如实报告区间与不足。

### 14.2 避免“只核查告警”的偏差

对告警事件做核查之外，还必须从未告警的矿点、河段与普通区域分层随机抽样，寻找漏报。对面积、地类、河宽、季节和云况分层记录抽样概率。

如果抽样比例不同，应在总体估计时加权。仅对高分值点进行现场核查，不能估计总体召回，也不能用来说明全市没有漏报。无法建立独立真值时，只报告已核查告警的命中情况及覆盖范围。

### 14.3 指标和试点目标

以下是**待业务确认的试点目标，不是当前已达到的性能**。采矿和采砂分别统计，不能用易检测的一类掩盖另一类失败。

| 指标 | 统计方法 | 初始目标或要求 |
|---|---|---|
| 来源可追溯 | 有完整产品、处理版本、合规依据/缺口说明的已发布事件占比 | 100% |
| 伪确定性错误 | 缺测标正常、查无公开许可即无证、模型直接确认违法的事件数 | 0 |
| 高优先级活动命中率 | 经独立核验确有目标活动的 P1/P2 数 / 已完成有效核验的 P1/P2 数 | 各通道争取不低于 80%；报告 95% 区间及未核验比例 |
| 可观测目标召回 | 在服务能力范围且具有有效观测的独立真值事件中被检出的比例 | 初步争取不低于 70%；同时报告不可观测事件比例 |
| 违法确认率 | 最终确认违法数 / 已完成相应业务结论的疑似合规冲突事件数 | 先建立基线，不预设虚假的高指标；排除非采掘和证据不足情况分别报告 |
| 处理时效 | `t_processed - t_discovered` 的 P50、P95 | 试点范围 P95 不超过 6 小时；不等同总发现延迟 |
| 通知时效 | 可发布到成功通知的时间 | P95 不超过 15 分钟 |
| 人工负荷 | 每周需研判事件数、平均时长、积压量 | 不超过已确认人力容量；初始可按每人每工作日 10 条详细研判测算 |
| 观测覆盖 | 按矿点数、河段长度及适当区域面积分别计算近期有效覆盖 | 覆盖与缺口都必须展示；不能只统计成功处理区域 |
| 稳定性 | 漏任务、重复事件、重复通知、上游中断恢复 | 回放与故障演练通过，重要失败有可见告警 |

“可观测召回”必须与全任务范围的检出情况并列，不能通过排除困难区域美化结果。含糊标签、没有核查的事件不进确定性精度分母，但数量和比例必须公开给内部验收人员。

### 14.4 发布门槛

- 只有底图和变化图：名称限定为“遥感监测试验”，不叫真实违法预警系统。
- 已有活动检测，但缺许可：可运行“疑似采掘活动监测”，所有合规问题待核。
- 权威许可、有效观测、解释性规则与核查闭环齐备：可在通过验收的样区运行“疑似违法线索预警”。
- 跨区域、跨季节及负荷验证通过：逐步扩大范围，保留不同区域能力标签。
- 未达到误报或负荷目标：调高质量门槛、改规则或缩小适用范围；不能仅隐藏低分告警而不计漏报。

## 十五、资源、预算与采购顺序

### 15.1 人员与计算

12 周试点建议至少明确：1 名遥感/GIS 主责、1 名系统开发主责，以及有固定时间投入的矿业、水利业务联系人和核查力量。可由现有人员兼任，但不能把业务核验工作完全压给开发人员。

试点计算可先按 8 至 16 CPU 核、32 至 64 GB 内存、约 2 TB SSD 可用空间评估，并进行样区压测。按窗口读取与分层缓存减少下载；GPU 不是首期必需品。全市容量应由实际瓦片数量、保留期及原始产品大小测算，不把试点配置直接当全市规格。

### 15.2 预算口径

不在缺少报价的情况下承诺总价。采用可核算预算表：

```text
试点总成本 = 人员投入 + 计算/存储 + 授权高分影像 + 外业核查
           + 可选设备/通信 + 安全与运维 + 经批准的预备费

高分影像成本 = 按供应商合同计费的有效范围/景数/任务次数
             + 云量保障、重拍、历史归档与使用授权相关费用

现场核查成本 = 核查批次 × 经确认的单批次成本
```

如需初始内部预算占位，计算与存储可暂按每月人民币 1,000 至 4,000 元评估。该数值仅为规划估算，不是采购报价，不含人工、高分数据、设备和外业；使用现有本机时可能没有这项新增云费用，但仍有备份与运维成本。

高分影像必须询价后单列，明确空间分辨率、有效成像日期、云量、地理定位精度、任务成功条件、可分析和可展示权利。不要为了追求全市高频高分覆盖而提前承诺不可承受的成本。

### 15.3 推荐投入顺序

1. 先保障权威许可和核查反馈渠道。
2. 再保障重点样区高分或现场验证，解决“变化到底是什么”。
3. 然后投入稳定的数据管道和专题页面。
4. 最后依据漏报类型决定增加商业重访、固定视频或模型训练。

不优先购买 3D 展示、全量 InSAR 计算或大模型服务。这些不能替代缺失的法律与现场依据。

## 十六、主要风险与停止条件

| 风险 | 影响 | 应对与停止条件 |
|---|---|---|
| 许可数据长期缺失 | 无法可靠筛查合规性 | 降级为活动监测；不得上线自动违法结论 |
| LiCSAR 等产品语义错误 | 产生虚假的沉降证据 | 隔离相关结果，重审产品与单位；验证前不进入业务 |
| 果园、梯田、工程误报 | 消耗核查力量 | 增加季节、水文与业务台账；按真实负荷调整适用范围 |
| 小目标、地下及短时作业 | 形成系统性漏报 | 明示能力缺口，重点点位补充授权高分/地面观测 |
| 云多或上游中断 | 时效不稳定 | 显示观测年龄与缺口；SAR 辅助但不伪装光学等价证据 |
| 边界或坐标偏移 | 错报越界 | 同名控制点抽查、转换记录、误差带；不合格边界禁用于精确判断 |
| 数据更新迟延 | 错认过期、无证或违规工程 | 维护时态版本；资料过期自动转待核 |
| 核查只挑高分事件 | 精度虚高、漏报未知 | 加入独立随机抽样与加权评估 |
| 非法数据曝光 | 业务与安全风险 | 分级授权、最小字段、导出审批；不上传未授权平台 |
| 人工队列失控 | 告警无法转化为行动 | 限制自动发布范围、增加研判、合并事件；不能靠堆叠告警证明系统有效 |
| 跨季节性能下降 | 实际运行偏离试点 | 分季节验证和漂移监控；必要时回退到规则与人工 |

以下任一情况出现，暂停相应区域的自动合规预警，保留基础监测：数据授权不清、关键许可无有效版本、定位精度不足、主要规则无法解释、持续误报超过承载能力、核查反馈中断或敏感数据可能泄露。

## 十九、最终建议

当前最重要的工作不是扩大图斑数量或叠加更多模型，而是补齐**正式资源与许可、可核验活动证据、稳定监测和业务反馈**四个条件。

**最终目标保持不变：发现真实问题并促成有效核查，而不是制造看似实时的地图和无法证明的违法概率。**
