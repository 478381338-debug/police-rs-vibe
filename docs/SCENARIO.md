# 自然因素情景推演说明（SCENARIO）

> 对应网页右侧“自然条件推演”抽屉和 API `POST /api/scenario/simulate`。  
> 代码：`app/scenario.py`；前端：`web/scenario.js`、`web/scenario.css`。

## 1. 它解决什么问题

旧版推演只能把未来降雨乘一个倍率、温度加一个偏移、风速乘一个倍率；用户无法直接输入“如果湿度升到多少、土壤更湿、NDVI 再降、再叠加多少毫米降雨”这类自然条件变化，也无法看到“真实预报基线”和“设定情景”的差别。

新版把推演拆成两层：

1. **真实预报基线**：Open-Meteo 未来逐小时预报原样聚合到逐日，不做任何人工修改。
2. **设定情景**：在基线上叠加用户输入的自然因素变化，再对每一个未来日重新评分。

两者使用同一套物理经验评分函数，差别只来自用户设定的变化。页面同时画出基线和情景两条曲线，并给出情景峰值、较基线增量、首次达到“较高/高”的日期。

## 2. 输入

| 输入 | 范围/单位 | 作用 |
|---|---|---|
| 点位 lon/lat | AOI 内 | 取最近气象点、格网、坡度和 NDVI |
| 灾种 | 火灾/滑坡/泥石流/洪涝/干旱/地灾 | 选择评分权重 |
| 未来降雨倍率 | 0.1–3.0 | 对未来每日降雨做乘法调整 |
| 额外降雨 mm/日 | 0–200 | 在倍率之上增加一个固定日降雨量 |
| 未来温度变化 °C | -15–+15 | 对未来日气温做偏移 |
| 未来风速倍率 | 0.2–3.0 | 对未来日风速做乘法调整 |
| 湿度变化 % | -50–+50 | 对未来日相对湿度做偏移 |
| 土壤湿度变化 | -0.30–+0.30 | 对未来土壤含水量做偏移 |
| NDVI 变化 | -0.50–+0.50 | 对植被/可燃物代理值做偏移 |
| 推演天数 | 1–14 天 | 生成逐日时间轴 |

情景计算方式（`_apply_scenario`）：

```text
precip_scenario = clamp(precip * rain_factor + precip_add, 0, 300)
temp_scenario   = temp + temp_offset
humidity_scenario = clamp(humidity + humidity_delta, 1, 100)
wind_scenario   = wind * wind_factor
soil_scenario   = clamp(soil + (rain_factor - 1) * 0.04 + soil_delta, 0.02, 0.55)
```

前 3/7 天累计降雨还会按 `0.7^i`、`0.85^i` 做前期降雨衰减后加入逐日情景，避免把一次降雨永久留在风险里。

## 3. 评分与等级

每个灾种使用透明的物理经验隶属度函数，再按固定权重合成 0–100 分：

- 火灾：温度、干空气、风速、短时降雨、3/7 天降雨、NDVI、坡度、道路可达性；
- 滑坡：坡度、3 天降雨、降雨强度、7 天降雨、土壤、历史异常、高程、道路；
- 泥石流：坡度、3 天降雨、降雨强度、7 天降雨、土壤、历史异常、沟谷、道路；
- 洪涝：3 天降雨、降雨强度、土壤、低洼、平坦度、历史异常、道路；
- 干旱：温度、干空气、7 天降雨、土壤、NDVI、风速、3 天降雨；
- 地灾：坡度、3 天降雨、土壤、历史异常、高程、道路。

具体公式和权重见 `app/scenario.py` 的 `_score()`；历史核查优先级权重见 `docs/MODEL.md`。

情景等级：

| 分数 | 等级 | 网页颜色 |
|---|---|---|
| ≥75 | 高风险 | 红 |
| 60–74.9 | 较高风险 | 橙 |
| 45–59.9 | 中等风险 | 黄 |
| <45 | 低风险 | 蓝 |

**这不是气象部门或自然资源部门的官方预警等级**，只是平台内部的情景分级。官方预警应以气象、水利、自然资源、应急管理等部门发布的信息为准。

## 4. 触发条件扫描

`_trigger_threshold()` 在情景峰值日保持其他条件不变，一次只扫描一个驱动因子：

- 洪涝/滑坡/泥石流/地灾：扫描 3 天累计降雨 0–300 mm；
- 火灾：扫描气温 -15–50°C；
- 干旱：扫描 7 天累计降雨 250→0 mm。

输出进入“较高风险（≥60）”和“高风险（≥75）”的近似驱动值。它是**模型敏感性扫描**，不是统计置信区间，也不是官方阈值；如果扫描上限内没达到，页面明确显示“未找到”，不会伪造一个数字。

## 5. API

### `POST /api/scenario/simulate`

请求示例：

```json
{
  "lon": 111.05,
  "lat": 40.9,
  "hazard": "flood_risk",
  "days": 14,
  "rain_factor": 2.2,
  "precip_add": 35,
  "temp_offset": 0,
  "wind_factor": 1.1,
  "humidity_delta": 15,
  "soil_delta": 0.10,
  "ndvi_delta": 0.0
}
```

响应关键字段：

- `baseline` / `scenario`：逐日点位分数序列；
- `baseline_peak` / `scenario_peak` / `delta_peak`；
- `first_orange`（≥60）/ `first_red`（≥75）；
- `frames`：逐日 180 个格网分数；
- `trigger`：单因子敏感性扫描结果；
- `scenario_changes`：本次实际生效的变化；
- `notice`：非官方预警声明。

## 6. 来源与“用了什么/没用什么”

已实际使用：

- Open-Meteo 逐小时天气预报作为真实基线（`https://api.open-meteo.com/v1/forecast`）；
- 本地真实格网坡度、高程、NDVI、人口暴露和道路距离；
- 中国气象局暴雨量级（3 小时 50/100 mm 等）作为当前危险指数的“量级对照”，不是官方预警；
- 中国降雨型滑坡/泥石流经验阈值（如短时降雨和前期降雨）作为评分因子的参考。

只作为方法参考、没有在运行时调用：

- `cffdrs` / `cffdrs_py` 的 FWI 思路（火灾天气指数）；
- SPI/SPEI 的干旱标准化思路；
- CLIMADA 的“致灾因子 × 暴露 × 脆弱性”框架；
- PySAL/esda 的空间自相关验证方法。

没有把上述 GPL/重型模型直接嵌入网站；也没有声称它们是官方模型。若要做业务级预警，应接入有资质的数据源并由气象/应急部门会商。

## 7. 已知限制

- 基线是 Open-Meteo 预报，存在预报误差；情景是“如果”，不是未来事实。
- 情景分数只表示自然因子风险，不含人口暴露，不能直接与左侧“当前危险指数”比较。
- 触发阈值是模型单因子扫描，不是官方阈值。
- 没有本地历史灾情标签，不能给出经过校准的发生概率。
- 网页公开、无登录，只能展示公开/示意数据；内部警力、案件和布防数据必须部署在内网并加认证。
